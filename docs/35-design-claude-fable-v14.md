# serial_nexus — Design Document

**Status:** Implemented and validated through the 0.3.0 release mark, including a real Tier-3 hardware rig; §16 records the post-completion reliability review. Sections 1–14 are normative for the system as built; §15 is the decision history.
**Scope:** A daemon and CLI client for managing serial ports as a graph of data-routing nodes.
**Targets:** Rust edition 2024. Linux is required; macOS is best-effort; Windows is out of scope (§13, §15.13).
**Names:** The project is `serial_nexus`; the daemon is `serial-nexus-daemon` and the CLI is `serial-nexus-ctl`.

This document records both the design and the reasoning. Sections 1–14 describe the system as settled. Section 15 is the historical record: each problem uncovered during design review, the path chosen, and its implications. A reader who wants only "what are we building" can stop after §14; a reader who wants "why is it built this way" should treat §15 as normative context for future changes.

---

## 1. Problem

Working with embedded targets over serial links looks simple — open `/dev/ttyUSB0`, run a terminal program — until several realities collide:

One physical serial port often carries several logical streams. Devices with a hardware or firmware multiplexer present multiple consoles, trace channels, and control channels interleaved on a single UART, framed by a device-specific protocol. Nothing off the shelf will split that port into separately usable streams.

Every interesting stream has more than one consumer. The same console needs an interactive terminal for the operator, a permanent log for forensics, and a forwarded copy on another machine — simultaneously, without the consumers interfering with each other or with the device.

Streams must cross machines. A lab machine physically wired to the devices is rarely the machine where people work. Streams need to travel over TCP or Unix sockets to a second daemon that re-exposes them as local pseudo-terminals and logs.

Writers must not collide. When two people (or a person and a script, on the same or different machines) write to one console, their bytes interleave at arbitrary boundaries and corrupt whatever line- or packet-oriented protocol the device speaks. Device maintenance requires disciplined, exclusive write access with an escape hatch for stealing it.

Ports come and go. USB serial adapters disappear and reappear; the same adapter does not always return as the same `/dev` path. Operator intent must survive replugging, daemon restarts, and device power cycles.

Existing tools each solve a slice: ser2net exposes ports over TCP, socat plumbs ad-hoc pipelines, conserver manages shared console access and logging. None of them compose demultiplexing, PTY fan-out, per-stream logging, re-multiplexing, and cross-machine forwarding under a single operator-owned configuration — and all three are copyleft-licensed, which this project may run as external tools but not link (§13). serial-nexus-daemon is a permissively-licensed daemon that composes all of the above as one explicit, inspectable graph.

## 2. Illustrating use case

This scenario exercised every design decision and is the reference configuration for the rest of the document.

A device exposes one physical serial port carrying a hardware multiplexer: several logical serial streams (main console, coprocessor console, trace output) interleaved by a protocol the operator knows. Computer A is wired to the device and runs serial-nexus-daemon with this configuration: a **serial port node** owns the physical port; a **codec node** speaking the device's multiplexing protocol (supplied as a compiled-in codec with configuration attributes, or via the exec codec escape hatch) demultiplexes the port into named **channels**; each channel fans out to a **PTY node** (an interactive pseudo-terminal for local operators), a **log node** (an append-only file with on-demand rotation), and one channel of a **leg node** — a socket transport that re-multiplexes all channels over a single TCP connection. Consoles with character quirks — bare-LF output, CR-expecting input — route through an optional per-console **map node** (§7.8) between the channel and its consumers, so each UART's peculiarities are written into configuration once instead of being re-negotiated at every terminal, log reader, and remote session.

Computer B, where the operators actually sit, runs serial-nexus-daemon with the mirror configuration: a leg node accepts the connection (bound to localhost on both ends and carried over SSH forwarding), announces the channel identities across the wire, and each bound channel fans out again into B-local PTY nodes and log nodes.

Maintenance works from either machine: an operator grabs the exclusive write lock on a channel, types into its PTY (or lets a script drive it), and releases. The write lock, backpressure, and purge rules guarantee that concurrent operators cannot interleave bytes and that stale, buffered commands never fire into a device that has rebooted in the meantime. When a second device is wired to computer A, its channels join the same leg, and computer B sees them appear as additional channel identities.

The apparent redundancy — demultiplex, then re-multiplex — is the point: once streams are first-class channels inside the graph, forwarding, logging, spying, and write arbitration apply uniformly to every stream regardless of how it entered the system.

## 3. Concepts and terminology

**Target system and host system.** Every stream in the graph runs between the *target system* — the device under control — and the *host system* — the world of consumers: terminals, logs, sockets, remote daemons. These are semantic anchors, not physical ones: on computer B, the target lies across a network hop, and a simulated device behind a pseudo-terminal is a target with no hardware at all. *Targetward* and *hostward* are the relative directions (what casual usage calls upstream and downstream).

**Nodes, endpoints, edges.** The daemon manages a graph. *Nodes* process data and move it in and out of the system. Nodes expose typed *endpoints*; an *edge* connects exactly two endpoints and carries a bidirectional byte stream. Edge direction encodes topological role, not data flow: data flows both ways along every edge (a console both prints and accepts input).

**Facing.** Every endpoint declares an orientation: it *faces target* or *faces host*, meaning the direction it looks along the target–host axis. A valid edge always joins one host-facing endpoint to one target-facing endpoint. Boundary nodes face inward: a serial port node's endpoint faces host (it offers the device's stream to consumers); PTY nodes and log nodes face target (they look back toward the device); a codec node faces target on its multiplexed side and host on its channels. Dual-role node types — leg nodes, existing-PTY connectors (§7.7, deferred — §14), serial ports used as outputs (§7.1, deferred — §14) — carry a `faces` configuration attribute. In the reference configuration, computer A's leg faces target (it consumes local channels for transport) and computer B's leg faces host (it offers the arriving channels to local consumers).

**Configuration and state.** Everything the daemon knows is either *configuration* — desired, operator-owned, round-trippable — or *state* — observed, environment-owned, reportable but never persisted. The governing invariant: **operators own the graph; the environment owns only state.** Configuration operations fail only on structural invalidity; environmental failure (a missing device, an unwritable directory) never changes the graph, only a node's state.

**Names and identities.** Nodes have operator-chosen *names*, used for configuration addressing and CLI verbs. Channels have codec-scoped *channel identities*, which are the names that cross the wire between daemons. The display form `node/channel` combines them for human output; neither is derived from device paths, and neither may contain `/` — the display form and the on-disk address encoding depend on it, so a violation is a structural validation error. Two further legality rules exist for the same reason — a name that cannot do its job is a structural error, not an operator's problem to discover at runtime: a name may not be empty or whitespace-only (§11, §12's spelling rule for identity fields, applied to names), and it is bounded in length. The bound is not cosmetic. A channel identity rides in the header of *every* frame that carries its bytes (§9), so the per-frame payload is the frame size minus the header minus the identity; an unbounded identity drives that to zero and leaves the targetward fragmenter unable to place a single byte — the one way §5's fragment-never-drop obligation degenerates into counting loss it could have prevented. A generous cap on a human-chosen label removes the failure mode by construction. A bare node name addresses the node's *default* endpoint — a serial node's single endpoint, a codec node's multiplexed side, a map node's host-facing side — while `node/channel` addresses a named channel; a leg node has no default endpoint, its socket living off-graph (§15.22, §15.24).

**Origins.** An *origin* is a hostward boundary through which bytes enter the graph traveling targetward: a PTY with a client attached, an accepted socket connection, the CLI's `send` verb, a remote daemon's leg. Write arbitration and backpressure both act on origins.

**Boundary nodes.** Nodes where the graph touches a kernel object with its own finite buffer and independent consumer: serial ports (both directions), PTY masters, sockets, files, and the exec codec's child stdio pipes (§15.22). All buffering, dropping, and flow-control policy lives at boundaries; the graph interior is policy-free (§5).

## 4. Graph model

The graph obeys three structural rules, checked at load and on every incremental operation:

1. Every edge joins exactly one host-facing endpoint to exactly one target-facing endpoint.
2. A host-facing endpoint may have any number of attached edges; a target-facing endpoint has exactly one.
3. The graph is acyclic.

Rule 2 carries most of the semantics. Fan-out is implicit at host-facing endpoints: hostward data arriving at the endpoint is broadcast to every attached edge, and targetward writes from the attached edges are arbitrated by that endpoint's write lock (§6). There is no tee node; "attach the PTY, the log, and the leg to channel 2" is expressed directly as three edges on one endpoint. The single-edge rule on target-facing endpoints enforces the *one-producer invariant*: behind every endpoint sits exactly one source of hostward data, which is what makes unrestricted reading safe by construction. The dual failure mode — two streams interleaving hostward into one consumer — is unrepresentable, and accidental duplicate delivery would require a node whose documented job is duplication. Merging streams is always explicit: the multi-input node doing it (a codec, or a future labeled-combiner) frames its inputs rather than interleaving raw bytes.

Data flows both directions along every edge; some endpoints simply never exercise one direction (a log node never writes targetward). Symmetric configurations — the daemon bridging two physical devices as a virtual null modem or man-in-the-middle — are legal; the operator declares one side the target, and the docs state plainly that the choice is a labeling judgment, not a property the daemon can infer.

## 5. Data plane

The design assumption is the modern common case: 3-wire UART (TX/RX/GND), no flow-control lines. Consequently no end-to-end flow control exists toward the host — the device transmits whether or not anyone listens — while real, persistent bottlenecks exist toward the target (the port drains at line rate). The data plane is built around that asymmetry.

**The interior contract.** Interior nodes are queue-free and policy-free. They may hold parser state (a partial frame, bounded by the codec's frame size) and a single-chunk holdover slot per direction, but never queues. All policy — buffering, dropping, pausing — lives at the boundary types: serial ports, PTY masters, sockets, files, and child stdio pipes (§15.22).

**Hostward flow is lossy at boundaries.** `deliver(chunk)` hostward is infallible and immediate: interior nodes transform and forward synchronously in the caller's context; host-facing endpoints broadcast to all attached edges; and each consuming boundary applies its own policy when its kernel object can't accept data — bounded buffering where configured, then counted drops. A slow spy costs itself data, never its neighbors.

**Targetward flow is backpressured to the origin.** `deliver(chunk)` targetward returns Accepted or Busy and never blocks. Busy propagates synchronously back to the origin, which stops reading its own kernel object until the path drains: the TCP window closes, the PTY client's write blocks — the kernel buffers on the client's side of the fence, and nothing is dropped. Commands are delayed, never lost. A transform that has already emitted output when downstream refuses parks it in its holdover slot, capping interior memory at one frame per node; boundaries announce writability, and the runtime drains parked holdover frames on that signal, independent of any new origin input, so no frame can be stranded behind a quiescent origin. If a port does have flow control configured (XON/XOFF or RTS/CTS remain ordinary port attributes; the 3-wire assumption is a default, not a constraint), the kernel pausing transmission surfaces as Busy, so hardware flow control transparently extends across the graph to remote writers. One obligation binds *every* component that frames targetward bytes — the wire, the envelope, and in-process codecs alike: an oversize producer chunk is fragmented, via the one shared helper, never skipped on encode error. This sentence exists because the skip-on-error variant of that bug shipped three times in three framers before review caught the last one (§15.27); the invariant is per-writer, not per-protocol.

**Serial ingest never blocks and never idles.** A configured serial node holds its port open (§7.1) and reads continuously. When nothing is attached, data is discarded with a counter rather than left to overflow the kernel: the alternative — not reading — fills the driver buffer, drops on overrun anyway, and greets the first consumer with a stale burst followed by a gap. Driver overrun counters (TIOCGICOUNT, where supported) are surfaced in state alongside the daemon's own discard counters, so loss is always visible and attributable.

**The replay ring.** Every host-facing endpoint carries a replay ring by default — `replay_ring = 65536` unless overridden, `0` to disable (§15.32) — a bounded ring of the most recent hostward bytes, retained solely so a late attacher sees what just happened: conserver's attach-and-see-the-panic feature, graduated from §14 with the web console (§17) as its driver, and now the default because a console without scrollback is a console that punishes arriving late. The cost is stated, not hidden: bounded memory per endpoint (64 KiB × a lab box's fan-out is a few MiB) and one mirrored copy of each hostward chunk into the tap feed — re-verified against the §15.19 throughput bar, never backpressuring the device. (One implementation constraint has tripwire status: the ring is bulk-copy circular storage, because a per-byte structure on this now-universal hot path is a throughput collapse — the benchmark caught exactly that when a byte-at-a-time deque first shipped, and the fix was the data structure, not an opt-out.) The ring is a feature buffer, explicitly not flow control, and it never substitutes for a log node — mechanically guaranteed by the accounting doctrine the audit forced: the tap/ring mirror is a spy *outside* the graph, with its own `feed_dropped` counter, and `discarded_unattached` counts graph-consumer absence independent of it, so a ring can never silently hide loss beyond its depth. A tap opened with replay receives the ring snapshot and then the live stream with an exact splice — no gap, no duplication — cheap to guarantee because snapshot and attachment happen inside one critical section on the runtime thread (§15.20's two-lane model doing double duty).

**Files are the exception that proves the boundary rule.** Regular-file writes cannot be made non-blocking (O_NONBLOCK is a no-op on them), so each log node owns a bounded queue feeding a dedicated writer task, with an overflow policy of drop-oldest-with-counters or fault-the-node — triggered in practice by full disks and slow network filesystems.

The data plane is a hybrid (§15.18, §15.19). Control, coordination, and low-rate paths — targetward flow, presence and termios polling — run on one async thread, with readiness for tty-family descriptors driven by non-blocking `poll(2)` under an adaptive idle backoff rather than epoll, because epoll misreports pty-master readiness (§15.18). Each high-rate hostward path — a serial port's reader, a PTY master's writer — runs on a dedicated blocking thread parked in blocking `poll(2)`, which costs nothing while idle and wakes the instant the fd is ready (§15.19). The synchronous deliver contract is context-agnostic and executes on whichever thread originates the data; cross-thread state is limited to atomic counters; socket boundaries use the async runtime's native socket types, which do not share the quirk.

## 6. Write arbitration

Reading is never arbitrated: the one-producer invariant (§4) makes hostward flow unambiguous, and every attachment may watch. Writing is arbitrated per host-facing endpoint: among all edges attached to an endpoint, at most one holds the exclusive write lock, and only the holder's bytes are read targetward. The lock is implemented as a gate on the §5 pause machinery — non-holders are simply not read from — so arbitration adds no new data path.

Each edge declares a **write mode**:

- `never` — the read-only capability. Log edges and spy PTYs; these attachments cannot contend for the lock at all. Taps (§17) are its dynamic form: connection-scoped, read-only attachments created over the control plane, each with a bounded queue and drop counters per §5, gone when their connection closes.
- `on-demand` — the default for interactive and programmatic origins (PTY clients, socket connections, the CLI). Acquisition is explicit via the control plane for named origins, and implicit for leg channels: a leg acquires when it has pending targetward bytes and the lock is free, and releases after a configurable idle interval or on peer disconnect.
- `held` — acquire-on-attach, held indefinitely. The demux codec's edge to the serial port holds that endpoint's lock permanently, because any other writer would corrupt the multiplexing protocol's framing on the wire. Stealing that lock is possible and stalls every channel — which is not a limitation but an accurate description of what raw injection does to a multiplexed link.

**Etiquette and the CLI.** The intended workflow for admin operations is grab, write, release — and the two verb families name different things (§15.20). `lock`/`unlock` name the **origin**, the writer being granted the floor (`serial-nexus-ctl lock console-a`), which the daemon resolves to the one host-facing endpoint that origin feeds — unambiguous by §4's single-edge rule. `send` names the **endpoint** (`serial-nexus-ctl send usb0 --line "..."`, or `send mux/ch2`), because the CLI is itself the transient origin there: it performs acquire-with-timeout, write, and release as one atomic daemon-side operation, joining the waiter queue below like any other contender and failing with the locked error at its deadline. Because exclusive is the default, even a sole on-demand origin must acquire before its bytes flow — single-console operators either adopt the grab-write-release habit or set `arbitration = "free-for-all"` and skip the ceremony. Acquisition happens out-of-band on the control socket because the data streams have no side channel, and in-band escape sequences would corrupt binary protocols.

**The purge invariant.** All purging is one rule with three instances: bytes offered while an origin lacked the floor are never delivered — they are drained and counted at the moment the floor question settles, which happens at grant (purge-on-acquire), at detach (purge-on-detach), and at device reconnection (purge-on-reconnect, the one sanctioned targetward drain, §7.1). Implicitly-acquiring wire origins are exempt from the grant instance only because data arrival *is* their floor request — there is no pre-grant interval to purge. The reconnect instance drains the parked targetward pipeline *to quiescence* — including a chunk held by a producer suspended mid-send — before the device goes active again; bytes still sitting in an origin's own kernel buffer remain the grant and detach instances' job, and a continuously producing origin is drained only to quiescence, not chased (§15.27). The detach instance covers one thing more than that kernel buffer, and it has to: a boundary reader may already have *taken* a payload off the client and be holding it because the endpoint cannot accept it yet (§7.2). That payload settles with the floor question like everything else — offered once more, then purged and counted — because carrying it across the release means delivering a departed console's typing under whatever origin holds the lock next, which is the interleave the exclusive floor exists to prevent, and on a merely stalled endpoint it is the stale-command hazard verbatim.

**Purge rules — the stale-command hazard.** Because non-holders are paused rather than dropped, a locked-out client can type into its kernel buffer, get no response, and walk away; when the lock later frees, minutes-old commands would fire into the device. Therefore: on explicit lock acquisition, the daemon drains and discards (with a counter) anything the origin buffered before the grant — safe by construction for correct clients, which acquire before writing; on origin detach without the lock, the backlog is likewise purged. Implicitly-acquiring leg channels are exempt from purge-on-acquire (data arrival is the acquisition trigger); the analogous hazard for legs and for reappearing serial devices is covered by purge-on-reconnect (§7.1, §7.4).

**Lifecycle.** The lock releases on explicit unlock and automatically on origin detach (slave closed, connection dropped). `serial-nexus-ctl lock --steal` exists for the hung-script case and is recorded in state so the previous holder can see what happened; an optional lease duration bounds a wedged session, its expiry guarded by the grant's generation so a stale timer can never release a later grant, and its firing following the normal release path — notification, then grant to the queue head. State reports holder, waiters, and per-origin purge counters per endpoint. A per-endpoint attribute `arbitration = exclusive | free-for-all` defaults to exclusive; free-for-all ("no lock") remains for machine-to-machine links coordinated elsewhere.

**Waiting and fairness.** Contention is managed by an explicit FIFO waiter queue per lock, not by racing wakeups. A plain `lock` against a held endpoint fails fast with the locked error; `lock --wait` joins the queue; `send` joins with its deadline. Grants pass to the queue head on every release path — explicit unlock, detach-release, lease expiry, and a stealer's own release — and steal bypasses the queue without destroying it. One class outranks the queue: a `held` origin that lost its lock to a steal reclaims it ahead of every on-demand waiter the moment it frees — "held indefinitely" is the promise, and granting a queued waiter a demultiplexer's lock would corrupt the very framing the hold protects (§15.23). The rule is an *acquisition-time* property, not a wake-ordering one: while a `held` origin is registered, `acquire` by any other origin is denied even on a free lock, so the reclaim wins deterministically rather than by scheduler luck — review found the wake-race version, and the fix lives in the pure state machine, where it is property-tested (§15.27). Two structural corollaries were review-hardened into load-time errors (§15.34): an edge feeding a codec's multiplexed endpoint must be `held` or `never` — an on-demand writer there can never legitimately win, so accepting the configuration was accepting a dead edge — and two `held` origins on one endpoint are refused with both offenders named, since two unconditional priorities cannot coexist. **Both corollaries are conditioned on the endpoint arbitrating at all**: a `free-for-all` host endpoint has no lock, so `held` and `on-demand` are behaviourally indistinguishable there, no writer can park, and neither rule has a hazard to prevent — refusing such a graph would reject a configuration that runs, with a stated reason that is false for it. The exemption is one predicate consulted by both rules, so it cannot be applied to one and forgotten on the other (review 32 `CORE-2`; the second rule already carried it, the first did not). Every grant, immediate or queued, runs purge-on-acquire before the origin's bytes flow. Waiting is cancel-safe: a deadline, a dropped control connection, teardown, or removal of the endpoint dequeues the waiter with a defined error, and a cancelled waiter costs nothing but its queue slot. Mechanically this is the two-lane control plane of §15.20: every lock transition is a synchronous critical section on the runtime thread, and a waiting verb suspends holding nothing — no borrows, no locks, only its place in line.

**Limits, documented.** The holder is an origin endpoint, not a process: two processes sharing one PTY slave are indistinguishable to the daemon. Cross-machine exclusion composes by nesting — the remote daemon's writers contend locally on their side, and the whole remote leg contends as one origin on this side, with backpressure crossing the TCP link — at the cost of blocking rather than fail-fast UX for remote contenders; explicit lock request/grant frames are a reserved wire capability (§9) for later. And poll-sampled presence has a documented blind spot: a client that closes and a different client that reopens the same slave within one poll interval are indistinguishable, so the successor inherits the lock on the detach-release path — explicit unlock is unaffected, exclusion across endpoints is unaffected, and the per-open generation epoch that would close the window is deferred (§14).

## 7. Node types

Each node type is specified as: endpoints and facing, configuration (operator-owned, round-trips through dump/load), state (observed, reported by the `state` verb), and behavior. Common to all node types: a `name` (configuration), a status of `active | waiting | faulted` with reason and timestamp (state), and the rule that environmental failure faults the node without failing the operation that created it.

### 7.1 Serial port node

One endpoint; faces host in the normal role. The target role — a physical port as an output leg toward another machine's tools — remains in the model but is refused as not implemented at load, a structural error naming the deferral (§14): review found the schema accepted an orientation nothing could drive. Codec and leg nodes keep both orientations. Configuration: device identity in resolver form (§12), termios parameters (baud, data bits, parity, stop bits), flow control (`none` default, `xon-xoff`, `rts-cts` — kebab-case is canonical and is what `dump` emits, with the unhyphenated `xonxoff`/`rtscts` accepted as aliases, §15.34), initial modem-line assertions, and hostward-consumer drop policy. State: resolved `/dev` path, status, daemon discard counters, driver overrun counters where available, current modem-line readings.

Behavior: the node opens with O_NOCTTY, takes TIOCEXCL so stray processes cannot share the port, applies configured termios and modem lines, and holds the port open for its lifetime — open/close toggles DTR on many USB adapters (the classic auto-reset), so line states must be deterministic. It reads continuously, discarding with counters when nothing is attached (§5). On read failure the node goes **faulted-and-wait**: hostward flow goes silent, targetward reports Busy so all origins pause, and the node polls the resolver (a stat every second or two — cheap, portable, and free of libudev's LGPL linkage) until *the same identity* reappears; a different adapter squatting on the old path is not adopted. Reopening reapplies configured termios, retakes TIOCEXCL, restores modem lines, and by default purges origin backlogs accumulated during the outage (the device likely power-cycled; twenty minutes of buffered commands must not fire into its boot prompt), with counters and a per-node override. The order inside that ritual is normative rather than incidental: the reopened port is **published on the node before the purge**, because the purge awaits, and a port the node's own ordered release cannot see is a port the `--replace` handover walks straight past — the daemon then EBUSYs against its own claim, which is the §15.38 D2 shape surviving in a second place. The reported cost is accepted as the more truthful of the two readings: for the width of the purge the node says `waiting` with its device open, which is exactly what a third party's `open(2)` already says, and a signal verb issued in that window is accepted and stays valid into `active`. Serial nodes leave the graph only by explicit configuration operations.

Giving back what the node asserted *on the tty* belongs to the port rather than to whichever exit path someone remembered: every route by which the node lets go of a device — clean teardown, the `--replace` handover (§15.38), a fault, the reconnect ritual, and a failure partway through the open ritual itself — returns **every tty-level assertion this node made** before the descriptor goes. Today that is two, and stating the rule over the class rather than over `TIOCEXCL` is the point: the exclusive claim taken at open, and a break condition one of the signal verbs below left standing. Both are tty state, not fd state, and outlive the fd exactly the same way — exclusivity until the tty's last close, break until *somebody* issues the clearing ioctl, which on a UART a `--replace` successor has just inherited is nobody. They are returned in that order, break first, so the line is transmitting normally before anyone else can open the port. DTR and RTS are deliberately excluded: driving them on the way out is an auto-reset pulse on the boards this whole area exists to protect, and unlike the other two they self-heal, since a successor's own `open(2)` re-raises DTR and the open ritual reapplies the configured levels. Taking `TIOCEXCL` as the example: the flag clears only at the tty's *last* close; on a pty-backed device (socat `PTY,link=`, QEMU `-serial pty`, the project's own doubles, all legal `raw:` inputs) a held master means that last close never arrives, so one leaked claim makes the device un-openable by every unprivileged process on the machine, permanently, surviving daemon exit — with the node's own reason flipping after a reconnect poll to a `Device or resource busy` that sends the operator hunting a squatter that is the daemon. The release is at-most-once for the mirror-image reason: an ordered release before a successor opens the same tty must not be undone by a late drop stripping the *successor's* claim off the tty they share (review 32 `RV-8`/`CONC-4`/`SERX-1`).

Control-plane verbs on this node: `send-break`, `set-modem`/`pulse-dtr` (and RTS), read modem lines — the signals a 3-wire-focused PTY cannot convey (§7.2). The two that hold a line asserted for a duration carry a stated maximum on `ms` — 60 seconds, deliberately far tighter than §11's general timer cap, which bounds retry intervals rather than hardware: this number holds a *physical* line down, a break garbling every byte the device transmits or DTR parked at a reset level, and it is the one input that makes the window in which an in-flight verb outlives its node arbitrarily wide. It is range-checked before the port is resolved and before anything is asserted (§11), so three extra digits are refused by name rather than learned from a console that never comes back. A signal is also scoped to the port it was issued against, not to the node's name: if the node is torn down, removed, replaced or simply reconnects while the assertion is in flight, the verb wakes at once and declines, and neither the assertion nor its deferred restore reaches whatever port the node holds afterwards — an fd and a line state outliving their node into a successor's ownership is the same class as the leaked claim above (review 32 `CTRL-1`/`SERX-2`). Declining is only half an answer, and it is the half that reads like the whole: a break the deferred restore no longer clears is still asserted *on the tty*, so scoping by itself turns an `ms`-bounded outage into an unbounded one — the successor reporting `active` and `open: true`, accepting every `send`, its driver `tx` counter climbing, and the peer receiving nothing until somebody destroys the tty. What actually leaves the line transmitting is the ordered release above: a bounded assertion is cleared when the port changes hands, by the port, not by whether its own verb survived long enough to restore it.

### 7.2 PTY node

One endpoint, faces target. Configuration: symlink `path` (required), `owner`/`mode` (default: daemon user, 0600; 0660 when a group is configured — applied to the slave device node, which is what gates open(2); accepted range `0o600 ..= 0o777`, one window carrying two rules, since a permission mode is nine bits and TOML rejects leading-zero integers: the ceiling names the whole family of three-digit *decimal* typos of an octal mode, of which `mode = 666` — 0o1232, owner `-w-` — is the one that used to load and then fault the node with an EACCES that never mentioned the mode, and the floor is the daemon's own access, because the node's setup chmods the slave and then opens it to prime the session), write mode (default `on-demand`; `never` makes a spy terminal), hostward drop policy, and an optional `advertised_baud` (default 115200) — cosmetic, since PTYs ignore baud, but it makes tcgetattr tell attached clients something sensible, and it may be set to mirror the paired serial node's configured rate (standard rates only — a nonstandard advertised value is skipped rather than approximated). State: allocated pts path, client-present flag, the client's current termios parameters (baud, character size, parity, flags), and drop counters.

Behavior: at creation the daemon allocates the pair, sets the baseline termios — raw, echo off, EXTPROC on — primes the pair by opening and closing the slave once (a never-opened master does not yet report HUP, so priming forces the canonical absent state and makes presence detection uniform from the node's first instant; kernel-verified by doctor P2), and creates the configured symlink to the pts node. Raw-and-no-echo is load-bearing: a fresh PTY echoes slave input back to the master and translates newlines, which builds feedback loops the moment data reflects. Packet mode (TIOCPKT) is enabled on the master; combined with EXTPROC, any client tcsetattr surfaces as a control packet, after which one tcgetattr updates the reported client parameters in state — TIOCPKT alone reports flushes and flow-control toggles but not baud changes, so EXTPROC is the necessary companion. Clients that rebuild termios from scratch clear EXTPROC; that clearing generates a final notification and the daemon re-asserts the flag through the master. A slow reconciliation poll (a few seconds; one ioctl, effectively free) backstops the mechanism's obscure corners and is the sole mechanism on macOS if EXTPROC behavior there disappoints. The daemon only *observes* client termios; propagation to hardware is deliberately deferred (§14), with an experiment path already available: subscribe to state changes and drive the serial node's configuration via RPC from a userspace tool.

Presence and HUP: the PTY outputs hostward data while at least one client holds the slave open, and discards (with counters) while none does — which conveniently also means the daemon never parks bytes in a kernel buffer nobody will read. Disconnect detection is the master's HUP condition; attach detection needs two mechanisms because no un-HUP event exists: terminal programs announce themselves instantly by calling tcsetattr (a packet-mode event), and a sub-second zero-timeout HUP-status check catches silent openers like `cat`. On last close, the daemon resets the pair's termios to the baseline **and discards whatever the pair still holds hostward** — the device output this session was sent and never read — so every client session starts deterministic in both of the senses that phrase has to carry: how the next session's bytes are *framed*, and *which bytes it sees at all*. Only the first half shipped originally, and the sentence read as though it covered both: the kernel keeps a departed session's undelivered output across the close, up to the pts input queue's depth (measured at ~13.8 KiB), and hands it to the next opener, so a fresh `picocom` opens onto the previous operator's scrollback. The discard is **counted** (`discarded_at_last_close`), because §5 permits a slow or absent consumer to cost itself data and never permits losing it invisibly — and this boundary was shedding kilobytes while `state` reported `discarded_no_client: 0`. Mechanically the daemon *reads the slave dry* rather than issuing `tcflush`: the queue belongs to the slave, and of the flush variants only a read reports how much it removed, which is the number §5 wants; a master `TCOFLUSH` also leaves the line discipline's own buffer behind, and a slave `TCIFLUSH` leaves a `TIOCPKT_FLUSHREAD` packet on the master that the next poll cannot tell from a client's session evidence. The baseline is a *contract* — raw, echo off, EXTPROC at session start — and the fd it is applied through is a platform arm (§15.30): Linux applies and resets through the master; BSD-family kernels reject termios on the master (ENOTTY), so macOS applies through a momentarily opened slave, and because macOS also resets a pty's termios to cooked on last close, the baseline is re-asserted on the presence *rising edge* — the arriving client then holds the slave and keeps the setting alive. A poll-latency window precedes that re-assert, consistent with the macOS poll-only observation story; interactive clients, which set their own raw termios, never notice. Presence has a second review-hardened rule (§15.36): last-close detection latches on *session evidence* — any successfully read master packet arms it, data or ioctl alike — because a client that opens, sets termios, and closes inside one poll window is a real session whose lock must release; the node's own baseline re-assert packet is then drained unconditionally (counted if it ever carries data, per §5) so it cannot re-arm the latch it triggered. The one deliberate residue: a bare open-and-close that touches nothing leaves no evidence to latch on — it also sent nothing to purge, and it self-heals on the next observed session. Presence means "at least one opener"; the daemon cannot tell sharers apart (§6).

Symlink rules: the configured path is configuration; the pts target is state. A pre-existing path faults the node (environmental) — except a symlink dangling into devpts, presumed to be our stale artifact from a crash, which is silently replaced. The symlink is unlinked on node removal and clean shutdown.

### 7.3 Log node

One endpoint, faces target; write mode is inherently `never` — a configured edge value is overridden to `never` at runtime and round-trips through dump/load only cosmetically. Configuration: directory, filename, overflow policy (drop-oldest with counters, or fault), and rotation-suffix padding (default three digits). State: current file, most recent rotation number, queued bytes, dropped bytes.

Behavior: raw bytes are appended via the bounded-queue-plus-writer-task shape required by regular-file semantics (§5). Rotation is on demand only — `serial-nexus-ctl rotate <node>` renames the current file to `<name>.NNN` with an incrementing counter (higher is newer; no logrotate-style shifting cascade) and reopens fresh at a byte boundary. The counter is state, recovered at node start by scanning the directory, never persisted. Removal and clean shutdown flush the queue within a bounded wait before closing.

### 7.4 Leg node

The cross-daemon transport: a socket carrying all of its channels multiplexed by the built-in link codec (§8, §9). Endpoints: one per configured channel, each with a channel identity; all channel endpoints face target on the sending side (`faces = target`, computer A: the leg consumes local channels) or host on the receiving side (`faces = host`, computer B: the leg offers arriving channels). Configuration: `faces`, transport (`tcp | unix`), `role = listen | connect`, address (loopback-only by default; any non-loopback bind or dial requires the deliberately ugly `insecure_bind = true`), reconnect backoff for the connect role, idle-release interval for implicit lock acquisition, purge-on-reconnect override, and the channel list with identities. State: peer address, connection status, per-channel binding — `bound`, `waiting` (configured here, not announced by the peer), and the peer's announced-but-unconfigured identities listed as `unbound`.

Behavior: one active peer per leg; concurrent second connections are refused. The connect role retries with backoff; an outage is faulted-and-wait, so targetward writers pause on existing machinery and purge-on-reconnect (default on) discards outage-era backlogs with counters. Wire announcements never grow the graph: they bind to configured channel identities, and everything else is visible state awaiting an operator (§8). The leg's two directions are independent: exhaustion of one half parks that half only — it never tears down the wire or the other direction (§15.24). SSH is the confidentiality and authentication layer for now — including OpenSSH streamlocal forwarding of Unix-socket legs, which skips TCP entirely (§9).

### 7.5 Codec node

A protocol transform: one multiplexed-side endpoint and N channel endpoints, instantiable in either orientation via `faces` on the multiplexed side (demultiplexer: multiplexed side faces target, channels face host; the mirror for re-multiplexing). Configuration: codec name (selecting from the compiled-in registry), an opaque attribute table the codec deserializes and validates itself (schema failure is structural and fails the load), and the channel list with identities. State: per-channel status and codec-specific counters (framing errors, resyncs). A codec's resync policy is its own: the reference codec resynchronizes by length-guidance — skip exactly the framed length, count one framing error — while the link codec, running on a reliable transport, treats any framing violation as a protocol error and never resyncs (§15.23). A standalone re-multiplexing instance (`faces = host`) is accepted by validation but waits for a driver; until one exists it is deferred work (§14).

### 7.6 Exec codec node

The escape hatch, packaged as an ordinary compiled-in codec (§8): configuration adds argv, environment, and restart backoff. The child process speaks the fixed envelope protocol on stdin/stdout — the same frame format as the link codec's wire protocol — translating between it and the device's proprietary framing; stderr passes through to daemon diagnostics. A crashed child faults the node and restarts with backoff. The child runs as the daemon's user (documented plainly). Because the child is a separate process speaking a documented protocol, protocol tools under any license, including copyleft, can be used unmodified without linking. The child's pipes are boundaries, not interior plumbing (§15.22): stdin and stdout are pumped as concurrently-polled directions so a blocked write can never starve the read, and the multiplexed raw stream travels on the reserved *empty* channel identity — which validation forbids for configured channels, so the reservation cannot collide.

### 7.7 Existing-terminal node

Connects to a pre-existing PTY or tty device by path (no hardware identity; the resolver passes paths through, §12). `faces` is configuration: `host` when the far side acts as the target — a QEMU serial console, a protocol simulator, a mock device for testing — or `target` when the daemon feeds a stream into some other program's terminal. Otherwise behaves as a boundary with the standard policies.

**This node remains in the model but is not implemented; a configuration naming it is refused (§14)** — the same treatment §7.1 gives the serial output leg, and stated here because it was previously absent from §14 while this section read in the present tense (review 32 `DEVR-3`). §3's "existing-PTY connectors" and §12's "Existing-terminal nodes … pass through as path identities" describe the same deferred node type.

### 7.8 Map node

The character-mapping transform — picocom's `--imap`/`--omap`, made a place in the graph instead of a flag on every client (§15.33). One target-facing endpoint, one host-facing endpoint; the host-facing side is the node's default endpoint and carries the full standard machinery — write lock, fan-out, taps, and the default replay ring, which means both a raw view (the upstream endpoint's ring) and a mapped view (the map's ring) exist by default. Configuration: `hostward` and `targetward`, each an ordered list of named mappings — the direction names the bytes being transformed, so `hostward` corresponds to picocom's `--imap` (device toward consumers) and `targetward` to `--omap` (consumers toward device); the flow-relative input/output vocabulary is rejected here for the same reason §15.3 rejected it everywhere else. The mapping vocabulary is picocom's: `crlf`, `crcrlf`, `igncr`, `lfcr`, `lfcrlf`, `ignlf`, `bsdel`, `delbs`, and the hex-display family (`spchex`, `tabhex`, `crhex`, `lfhex`, `8bithex`, `nrmhex`) — where `spchex`, per the upstream oracle, hexes the *control class* (DEL and controls other than tab, LF, CR), never the space character (§15.34). An unknown name is a structural error; an empty list is the identity; within a direction, the **first matching rule per input byte wins**, so order resolves conflicts deterministically.

Behavior: every rule is a stateless byte-to-byte-sequence substitution (possibly empty — deletion), so chunk boundaries are irrelevant by construction, no parser state exists, and this is deliberately *not* a codec — no channels, no frames, no resync — just §5's interior contract at its simplest. Output is bounded at k× input, where k is the largest expansion among the active rules (2 for the CRLF pair, 4 for the hex family), so the holdover slot's memory bound survives expansion. State reports per-direction byte counters and per-rule substitution counts — the cheap way to discover which quirk a mystery console actually has. The map's targetward edge into the upstream endpoint defaults to `held`, the demux's pattern with softer stakes: bypassing a map is not corruption, merely unmapped, so steal-to-bypass is a legitimate, visible act, and the addressing states intent — `send` at the map's endpoint speaks mapped, `send` at the upstream endpoint (post-steal) speaks raw.

## 8. Codecs and extensibility

A **codec** is a multi-channel framing transform: it converts between one multiplexed byte stream and N channels, in both directions, emitting and consuming per-channel events drawn from a small vocabulary — `data`, `open`, `close`, `error`. One implementation serves both orientations; the node's `faces` attribute selects which. Edges always carry raw bytes; all framing knowledge is internal to codec nodes, which keeps the interior contract (§5) intact — a codec may hold a partial frame, bounded by its frame size, and nothing else.

**Static and announced channels.** Hardware mux codecs declare their channel set from configuration, so their endpoints exist at load time. The link codec inside leg nodes instead *announces* channels over the wire — and an announcement must not grow the graph. The binding rule reconciles this with the operators-own-the-graph invariant: announcements bind to channel identities the receiving configuration already declares; announced-but-unconfigured channels appear in state as `unbound` with no endpoints and no attachments; configured-but-unannounced endpoints sit in `waiting` — the same state family as an unplugged serial port, reusing faulted-and-wait wholesale.

**Registry and workspace.** The project is a multi-crate Cargo workspace. A `serial_nexus_codec_api` crate defines the codec trait, the event vocabulary, and the envelope frame types; codec crates depend on it and never on the daemon. Compiled-in codecs live in an explicit registry — a name-to-factory table populated with the built-ins (each behind a Cargo feature, so minimal builds drop what they don't need) and extensible by an embedding binary (§15.26) — still no linker-magic auto-registration and no dynamic loading. A registration that collides with an existing name is a startup error, before any configuration is read.

**Embedding and out-of-tree codecs (§15.26).** The daemon is a library with a thin binary: `serial_nexus_daemon` exposes a deliberately narrow entry surface — run options mirroring the CLI flags, the codec registry, and the version constants — with everything else private. An out-of-tree repository ships two small crates: a codec crate depending only on `serial_nexus_codec_api`, and a custom daemon binary whose `main` is a dozen lines wiring `Registry::with_builtins().register(...)` into `serial_nexus_daemon::run`. Everything else in the ecosystem works against that binary unchanged — `serial-nexus-ctl`, `serial-nexus-sim`, `serial-nexus-doctor`, and the validation scripts speak RPC and the envelope, never the codec list — which is §15.16 paying out a second time. The daemon reports its registered codec names (and the wire/envelope versions) through the `info` verb, and an unknown codec name in configuration fails structurally with the available list in the error, so tools discover capabilities rather than assume them. The supported extension surface is exactly two contracts, both semver'd: `serial_nexus_codec_api` for in-process codecs, and the `serial_nexus_daemon` entry API for embedding; an in-tree external-consumer template, built by CI from a consumer's position, keeps the pattern compiling by proof rather than promise. One narrow, *named* exception to "everything else private" exists and is bounded by its own rule (§15.26): a `unstable_fuzz_api` module in the crates whose parsers face untrusted bytes, re-exporting exactly what the fuzz harness drives and disclaiming stability in its first sentence. The exec path (§7.6) remains the zero-Rust alternative for other languages and copyleft tooling, with the same conformance harness treatment (§15.26). Codec attributes arrive as an opaque table (from the TOML/JSON configuration) that the codec deserializes via serde into its own types; a schema failure is structural and fails the load or operation, consistent with §11.

**The envelope.** The exec codec's child-process interface and the daemon-to-daemon wire framing are two *contracts* with distinct stability promises: the envelope is public and versioned for external codec authors; the wire protocol is internal between daemons and free to evolve under the §9 contract. In v1 they deliberately share one frame format and one implementation, defined in `serial_nexus_codec_api` — one specification to document, pipe-testable codecs, and any-language authorship (including wrapping copyleft protocol tools) behind a stable, non-linking interface — but they version independently, and evolving the wire must never break envelope users.

## 9. Wire protocol

The framing protocol is a module, not a design element. The design imposes a contract on any leg framing and otherwise stays out of it: frame layouts, handshake encodings, and substrate choices are properties of a particular protocol version and must not cascade into the rest of the system. Any framing must:

1. Multiplex any number of independent bidirectional byte channels over one reliable, ordered transport, addressing them by channel identity carried losslessly.
2. Transport the §8 event vocabulary per channel — `data`, `open`, `close`, `error` — and be evolvable to additional per-channel control events (the reserved lock request/grant relay of §6 depends on this).
3. Convey each peer's channel announcements, so the receiving daemon computes `bound`/`waiting`/`unbound` state without operator involvement.
4. Declare a bounded maximum frame size, so the interior one-frame holdover (§5) and receive-side reassembly remain bounded-memory (v1: a fixed constant; negotiable later). A producer chunk exceeding the bound is fragmented across consecutive `data` frames — never rejected, never dropped (§15.24).
5. Preserve the targetward no-drop guarantee end to end — at minimum through whole-connection backpressure, optionally through per-channel flow control. The protocol itself never drops; hostward loss remains a counted boundary policy of the sending daemon's leg.
6. Identify its version and negotiate optional capabilities at connection start, refusing mismatches cleanly with the reason surfaced in leg state.

Conversely, the design keeps — and names as such — the aspects that exist to admit some form of protocol: identity-keyed channels, the event vocabulary as lingua franca, Accepted/Busy as a flow-control hook, binding states in leg state, and capability-conditional features.

**The v1 protocol.** A custom framing satisfying the contract minimally: length-prefixed frames carrying a channel identity and a type, opened by a `hello` frame (magic number, protocol version, channel announcements, capability bitset). The hello is a distinct wire construct rather than a fifth event kind — it reuses the length prefix and opens with the magic, validated together with the version before any version-specific field, so a mismatch always refuses *as* a mismatch and the envelope's golden vectors stay byte-frozen; the wire and envelope versions are independent, cashing §15.15's two-contract split (§15.24). yamux was evaluated as a substrate — permissively licensed, with per-stream flow control — and declined for v1 because identities, announcements, and the envelope sharing below are exactly what it would not provide; under this contract, swapping the substrate later is a contained change (§14). Two v1 properties are documented as protocol properties, not design properties: flow control is whole-connection only, so targetward traffic is subject to head-of-line blocking — one Busy targetward path stalls all channels' targetward flow across that leg, acceptable because targetward traffic is human-scale command entry, and hostward flow is unaffected — and the v1 frame format doubles as the exec-codec envelope's v1 implementation, though the two are separately versioned contracts (§8) and wire evolution must never break envelope users.

Security posture, version one: legs bind and dial loopback only; SSH port forwarding (or streamlocal forwarding for Unix-socket legs) provides confidentiality and authentication between machines. Non-loopback addresses require `insecure_bind = true` — a named footgun beats the patched binary someone would otherwise ship. Serial consoles are frequently root shells and bootloader prompts; the documentation says so in exactly those words. In-daemon TLS is deferred work (§14).

## 10. Control plane

The daemon listens on a Unix domain socket: `/run/serial-nexus-daemon.sock` when running as root, `$XDG_RUNTIME_DIR/serial-nexus-daemon.sock` otherwise, either overridden by a command-line argument. Socket permissions **are** the authorization model — whoever can open the socket owns every console — with mode 0600 by default and flags to widen to a group; the standard stale-socket unlink dance runs at startup, and the socket is removed on clean shutdown. SO_PEERCRED remains available for finer authorization later without protocol changes.

The protocol is JSON-RPC 2.0, hand-rolled over newline-delimited JSON — a page of serde types, no framework crate. Request/response correlation supports concurrent CLI clients (mutations are serialized daemon-side); id-less notifications are the natural shape for subscriptions: a `subscribe` verb streams node status transitions, lock changes, client-termios updates, and counter snapshots. Batch arrays are rejected outright, deleting the specification's awkward corner. Everything is debuggable with socat and jq.

**Waiting verbs.** Some arbitration verbs cannot complete immediately — `lock --wait`, `send`'s acquire-with-timeout — and the control plane runs them on two lanes (§15.20): every state transition remains a synchronous critical section on the runtime thread, exactly as before, and a verb that must wait suspends *between* transitions holding nothing, re-attempting inside a fresh critical section when woken. "Mutations are serialized" therefore survives unchanged in meaning while concurrent connections keep flowing past a parked waiter. Lock transitions — acquire, release, steal, lease expiry — are additionally emitted as immediate id-less notifications to subscribers; the periodic state snapshot is a floor for observability, never the delivery mechanism. Cancellation is deliberately indistinguishable from client death: EOF on a connection's request half cancels that connection's waiting verbs, because a half-close and a killed client look identical at read time, and a keep-awaiting policy would strand the killed waiter — so a raw-socket client must hold its write half open across a wait (`serial-nexus-ctl` does; the `echo | socat` idiom does not, and the docs say so, §15.27). One waiting verb may be in flight per connection: a request pipelined behind a parked wait is refused with its own error while the connection — and the parked wait — survive intact; a client wanting concurrency opens a second connection, which costs nothing (§15.34).

**Taps.** `tap.open <endpoint> [--replay]` attaches a connection-scoped, read-only observer to a host-facing endpoint and streams its hostward bytes as id-less `tap.data` notifications on that connection, base64-chunked; `tap.close` or the connection dropping detaches it. A tap is a §5 boundary consumer in miniature — bounded queue, counted drops, a slow tab costs only itself — and with `--replay` it is preceded by the endpoint's ring (§5) with the exact-splice guarantee. Every `tap.data` frame carries the endpoint's monotonic hostward byte *offset*, replay reports its `from_offset` and the `epoch` of the offset space that offset counts in (§15.38), and `info` exposes a per-boot daemon `instance` nonce — together these let a reconnecting client (the browser history of §17) trim replay overlap exactly and detect counter resets, instead of appending ring-depth duplicates on every reload (§15.32). When graph mutation removes a tapped endpoint (`load --replace`, teardown, cascade removal), the tap does not silently die: the daemon emits a `tap.closed` notification carrying the reason, and a `tap.close` for an already-dead tap is a plain error — clients re-anchor instead of guessing (§15.34). Taps never appear in configuration or dump: they are state, scoped to a connection.

The verb surface, grouped: configuration (`load`, `load --replace`, `dump`, `add-node`, `remove-node [--cascade]`, `connect`, `disconnect`; `set-attribute` remains deferred, §14); observation (`state`, `subscribe`, `info`, `ports` — the resolver's passive enumeration of the serial devices it can see, each carrying the identity that would bind it and the node that already does, if any — and `tap.open`/`tap.close`); arbitration (`lock [--steal] [--wait] [--lease]`, `unlock`, `send`); logging (`rotate`); serial signals (`send-break`, `set-modem`, `pulse-dtr`); lifecycle (`teardown`, `shutdown`). `serial-nexus-ctl` is a thin presentation layer over that surface — deliberately nothing more.

**CLI shape is presentation, not contract.** The CLI's shape — subcommand names and hierarchy, argument names, output formatting — will iterate on feedback from its users, human and AI agent alike, and the daemon must stay flexible to that iteration: nothing in `serial-nexus-daemon` may depend on how the CLI spells things. The stable surface is the RPC method set and its JSON schemas; the verb list above names semantic operations, not command-line spellings, and a CLI subcommand may be renamed, regrouped, or composed from several RPCs without any daemon change. All human-oriented rendering — tables, prose, color — lives in the CLI; the daemon returns structured results only, which makes a raw JSON pass-through mode essentially free and gives AI agents the choice of driving the CLI or speaking JSON-RPC to the socket directly. Version skew between CLI and daemon degrades gracefully by construction: JSON-RPC's standard method-not-found error tells a mismatched CLI exactly which operations this daemon lacks. The two surfaces evolve on different budgets — the RPC surface deliberately, additively where possible; the CLI shape freely.

Windows is out of scope, declared loudly rather than left ambiguous: PTY nodes have no Windows equivalent (ConPTY hosts console applications; it does not emulate serial devices), and the control socket assumes Unix domain sockets. The declaration deletes an interprocess-abstraction layer, keeps the PTY story purely POSIX, and is accepted with eyes open: supporting Windows later would be a redesign, not a port.

## 11. Configuration lifecycle

**Load is accepted only on an empty graph** — at daemon startup or after explicit teardown; `load --replace` composes teardown-then-load so nobody scripts it by hand. Reconciling a new configuration file against a running graph (diffing) is deliberately deferred (§14); until then, running graphs are modified through the incremental verbs, which validate against the same structural rules as load and touch only what they name — with the shipped surface being `add-node`, `remove-node --cascade`, `connect`, `disconnect`, and `load --replace`. Edge surgery runs the *same* critical-section structural validation as load (§15.35), so the rules above are not load-only: an illegal `connect` is refused naming the rule with nothing changed. `set-attribute` (attribute surgery on a live node) alone remains deferred (§14, §15.25). `remove-node` refuses while edges are attached unless `--cascade`; removal flushes log queues within a bounded wait.

**Load is structurally atomic.** The entire file is validated — the three graph rules (§4), name and identity legality (no `/`, no empties, no whitespace-only names, and the §3 length bound, no duplicate node names or channel identities), attribute schemas including codec tables — before anything is created; a structural error creates nothing. *(Qualified per review 37, 37-CFG-1, disposition **justify**, implementation-notes §3.24: this list also named "resolver-input well-formedness", which `load` deliberately does not check. Resolver-input well-formedness is `add-node`'s **capture** rule — the input-to-identity direction runs once, at add time (§12), and `resolve_input` has no other caller. Load must never require a device's identity string to be re-resolvable or its syntax re-parsed, because a configuration loaded by identity has to come up with the hardware absent; a node whose identity no longer binds comes up `waiting`, which is the environmental-failure arm below rather than a structural refusal. The code is right and the sentence was the stale side.)* Three rules hold across the whole schema, review-hardened (§15.34): every numeric attribute carries a stated maximum and is range-checked structurally — an absurd `replay_ring` or `hostward_buffer` is a named error, never an allocation; unknown configuration keys are refused naming the key, so a typo cannot silently become a default; and a non-empty source that parses to an *empty* graph is refused rather than obeyed, because under `--replace` that composition is an unannounced `teardown` reporting success. Environmental failures never fail a load: nodes whose environment is missing come up faulted-and-wait or waiting, visible in state, healing on their own. This is the operators-own-the-graph invariant in operational form.

**Dump round-trips.** `dump` emits configuration only, in exactly the load format; it is the migration story and the backup story. `state` is a separate verb for everything observed. The split is enforced mechanically by the schema: state fields simply do not exist in the configuration types.

**The daemon persists its own configuration.** After each config-mutating verb — never on read or arbitration traffic — the daemon snapshots configuration (same format, atomic tmp-plus-rename) to a state file; startup prefers the state file over `--config`. The default path is socket-adjacent (`<socket-stem>.state.toml` — the socket's *stem*, so `/run/serial-nexus-daemon.sock` yields `/run/serial-nexus-daemon.state.toml`, not `serial-nexus-daemon.sock.state.toml`): session-durable, restart-recovering, per-daemon-unique so parallel test daemons never share state; `--state-file` opts into reboot durability (§15.25). One consequence of using the stem is worth stating rather than discovering: two daemons whose socket paths differ only in extension (`a.sock`, `a.socket`) derive the *same* state file, so parallel daemons that must not share state need distinct stems or an explicit `--state-file` (§15.34, review 32 RV-6). Clean shutdown preserves the graph for restart; only the explicit `teardown` verb persists an empty one. A snapshot write failure is logged and never corrupts the running graph. A restart with devices missing simply comes up faulted and heals — restart, replug, and first boot are the same code path.

## 12. Device identity

Operator input naming a serial port — a raw `/dev` path or a device serial number — is converted by the **resolver** into a canonical, structured identity stored in configuration: `usb:<vid>:<pid>:<serial>:<iface>` in the common case. The resolved `/dev/tty*` path is state. The resolver runs in two directions: input-to-identity once, at add time; identity-to-current-path at every open and every faulted-and-wait recheck. On Linux both directions read the *same* source — the `<sys-root>/class/tty` device listing plus the sysfs ancestor walk that derives an identity from it — with `/dev/serial/by-id` as a fast path over that listing rather than an alternative to it; still no dependencies, no libudev. Reading one source is a rule, not an implementation note, because the two ways it can be broken are the resolver's two worst failures and both were shipping: capture that walks sysfs while resolution reads only by-id mints an identity the daemon can never honour — an environment with `/sys` and no udev serial links (a container handed a bare `--device=/dev/ttyUSB0`, an image without `60-serial.rules`) accepts the add, populates the resolved path, and then waits forever for a device that is right there — and a duplicate-serial guard that counts by-id link *names* cannot fire where the hazard is duplicate *devices*, since udev publishes exactly one link per colliding name (review 32 `RES-1`/`RES-2`, §15.10). One consequence worth stating as a rule: adding a node by raw path requires the device present at that moment (identity must be captured); adding or loading by identity never does, which is why dump emits identities and why configurations survive cold starts with hardware unplugged.

The real world requires a fallback chain: adapters with absent or duplicated serial numbers degrade to topology identity (by-path: "whatever occupies this physical port"), and finally to a raw-path escape hatch carrying a documented instability warning. Multi-port adapters — one serial number, several UARTs — are why the interface index is part of the identity. Identity fields have one spelling rule, sharpened by review: an absent serial or interface is written `-`, never left empty; empty or whitespace-only fields are malformed at add time, and a whitespace-only sysfs serial normalizes to absent at the source so it degrades to by-path instead of minting a wrong-device-prone `usb:vid:pid::iface`. (Configs persisted before that fix hold the retired empty-field form; such nodes come up `waiting` until re-added — a safe, operator-recoverable, and intended retirement, §15.27.) Existing-terminal nodes (§7.7, deferred — §14) would have no hardware identity and pass through as path identities. At add time the CLI echoes the resolved identity in human terms ("bound: FTDI FT232R, serial A6008isP, interface 0") so the operator notices if the wrong physical device answered. The ambiguous case is where that echo has to say more than "bound": an identity two present devices answer to binds nothing, and `add-node` returns it carrying a warning that names every device answering and points at the by-path identity `ports` lists for each. Through `load` or a startup from the state file there is no echo to read, so the same refusal surfaces the way every other unbindable device does — the node sits in `waiting`, indistinguishably from an absent one, which is the honest residue of a resolution direction that answers with a path and nothing else; `ports` is where the two clones are visible, each under the by-path identity that does pin it (§15.10). The `ports` verb (§15.35) is the resolver's enumeration face: it lists candidate serial devices with identity, current path, and whether a graph node already binds them — and it is strictly *passive*, built from by-id readlinks and sysfs (`cu.*` scanning on macOS), never `open(2)`, because opening a port to look at it toggles DTR on exactly the adapters people care about. macOS has no by-id tree; an IOKit-backed resolver is deferred (§14), with raw `cu.*` paths as the interim.

## 13. Platform support and licensing

**Linux** is the required platform and the one all mechanisms are specified against. **macOS** is best-effort and now *runtime-verified* on real hardware (§15.30): the full test suite passes at parity with Linux, the serial data plane is byte-exact across a physical crossover rig, and TIOCEXCL holds; the deltas are the `cu.*`-not-`tty.*` device convention, the missing by-id tree (§12), driver counters gracefully absent (TIOCGICOUNT is Linux-only), the §7.2 termios-and-flush platform arm (§15.30), and one test-infrastructure limit — a macOS pts cannot stand in for a serial device (the platform's baud ioctl rejects it), so serial-*device* tests there self-skip in favor of the real-rig gate, the §16.7 doctrine applied. The validation suite itself is a cross-platform Rust crate (§15.31). **Windows** is out of scope (§10).

Supporting several systems is a stated requirement — a spread of Linux kernel and distribution versions, plus the macOS tier — and capability differences are discovered by tooling, not by bug reports. The project ships **`serial-nexus-doctor`**, a diagnostic binary that runs every kernel-behavior probe the design depends on (EXTPROC/TIOCPKT signaling, PTY presence semantics, exclusive-open and unplug error surfaces, device-identity resolution — asked about *devices*, never about the by-id directory, so the diagnostic cannot skip in the one environment §12 grew a fallback for) plus environment checks (device permissions, group membership, by-id tree presence, whose absence is `degraded` when devices are visible another way rather than reported as no adapter), and emits a copy-pasteable Markdown report — the expected first attachment on any support request — with a `--json` twin for CI. The daemon never consumes doctor output: its degradation paths (for example §7.2's reconciliation poll) are unconditional, so a wrong probe can mislead a developer but never the data plane. Hardware validation follows a **no-target doctrine**: nothing in the project's own test matrix requires a real device. A dangling USB-serial converter — plugged in, wired to nothing — exercises identity, enumeration, exclusivity, unplug, and replug; a jumper between one converter's TX and RX adds a true driver-level data path; two converters cross-wired as a null modem add independently clocked baud verification, framing/parity/break observation, modem-line signaling, and a physical instance of §4's symmetric configuration. The doctor certifies these rigs itself (§15.21): an opt-in probe discovers which named ports are dangling, looped, or cross-paired — verifying pairs in both directions, so a half-crossed wire is named rather than mysterious — and characterizes what the rig supports (rate-ladder integrity including nonstandard rates, deliberate mismatches proving the error counters observable, break reception, a modem-line map), producing the certificate every tiered checklist run starts from. *(Read the §15.21 annotation for what the shipped certificate actually contains: a deliberate **baud** mismatch and local break **assertion**, not a parity mismatch, break reception, or far-side modem signalling — review 37, 37-TOOL-3.)* The boundary stays crisp: the doctor certifies the rig; it never drives the daemon through it. Beyond rigs, the doctor is also the design's kernel-contact instrument (§15.36): probes P6–P12 measure the pty and serial behaviors this design's arguments rest on — last-close readiness, what collapsed sessions leave readable, epoll-versus-poll agreement, timer granularity, pty buffer depth, line-state counters, and the session-boundary edge (§15.39) — each emitting its raw measurements as structured JSON, not just a verdict, and reporting a kernel that *differs* as `degraded` with the observation named, never `unsupported`. New kernels get diffed, not assumed.

Dependency licensing policy: permissive licenses only (MIT, Apache-2.0, BSD) for anything linked; no copyleft crates, including weak copyleft; copyleft *tools and daemons* may be used unmodified as external processes. The rule governs what serial_nexus links, not who links serial_nexus: out-of-tree codecs and embedding daemons (§15.26) are an intended use the project's own permissive licensing exists to allow. Selections under that policy: **serial2** (BSD-2-Clause OR Apache-2.0) for port I/O — settings, custom baud rates, modem-line control for the §7.1 verbs, and break — driven asynchronously by the daemon's own poll-based readiness (§15.18) over a non-blocking fd the daemon sets non-blocking itself, with `TIOCEXCL` and later `TIOCGICOUNT` issued directly on the raw fd through the daemon's `sys` module. *(Corrected per review 37, 37-SER-3: this clause read "opened blocking and driven asynchronously", which is false of the pinned dependency — serial2 0.2.37's `SerialPort::open` passes `O_NONBLOCK | O_NOCTTY` as custom open flags and never clears them, so the fd arrives non-blocking. The daemon's own `set_nonblocking` on it is therefore redundancy, and deliberately kept: the readiness loop's correctness must not rest on a dependency's open flags, which are not part of its published API. Nothing about the design changes — only the sentence's account of who sets the flag.)* (`serial2-tokio` was originally selected alongside it and was dropped during implementation: it exposes no accessor for the inner fd, which the exclusivity and counter ioctls require — exactly the contingency §15.1 planned for.) The rejected alternative remains the ecosystem-default **serialport** stack, which is MPL-2.0 (weak copyleft) and stays in the dependency tree even under the MIT-badged tokio-serial/mio-serial wrappers. PTY syscalls come from **nix** (MIT) or **rustix** (Apache-2.0 OR MIT); raw termios via the same crates is the fallback if serial2 ever falls short. The remaining stack is the permissive standard set: tokio, serde, clap, bytes, tracing. Deliberately avoided: libudev bindings (LGPL linkage; hotplug uses resolver polling, with raw kernel uevent netlink as a dependency-free Linux upgrade), and linked use of ser2net/gensio, socat, or conserver — all valuable prior art, all copyleft, all fine to run beside the daemon.

## 14. Deferred work

Recorded so deferral stays deliberate: configuration diffing/reconciliation against a running graph (load-on-empty is the v1 constraint); native client-termios propagation to hardware (observe-only now; the subscribe-plus-RPC experiment path exists precisely to inform this); lock request/grant wire frames for fail-fast cross-machine arbitration (capability bit reserved); the conserver-style attach-time replay ring, which has graduated out of this list into §5 and §17 with the web console as its driver; an explicit labeled-combiner node for merged logs; in-daemon TLS and non-loopback legs; uevent-based hotplug detection replacing the resolver poll; an IOKit-backed macOS resolver; swapping the framing substrate (yamux) if per-channel flow control is ever needed — a contained change under the §9 contract; systemd socket activation; a per-open generation epoch on PTY slaves, closing §6's sub-interval close-and-reopen window on the detach-release path; a driver for standalone re-multiplexing codec instances (`faces = host`), which today load and wait (§7.5); `set-attribute` (attribute surgery on live nodes; remove-and-re-add covers it) — `connect` and `disconnect` left this list with §15.35; the serial output leg (`faces = target`, §7.1), accepted in the model but refused until a driving use case arrives; and the **existing-terminal node (§7.7)**, specified in the model and likewise not implemented — a configuration naming it is refused, listing the node kinds that do exist.

## 15. Historical decisions

Each subsection records a problem uncovered during design review, the decision taken, and its implications. These are the document's ADRs; changing one later means re-reading its implications, not just its decision.

### 15.1 The serial crate licensing landmine

**Problem.** The ecosystem-default `serialport` crate is MPL-2.0 — weak copyleft, excluded by this project's licensing policy — and the MIT-badged async wrappers (`mio-serial`, `tokio-serial`) keep it in the dependency tree; mio-serial's own documentation describes itself as a Larger Work over serialport-rs. The obvious dependency choice silently violated a stated constraint.
**Decision.** Use `serial2`/`serial2-tokio` (BSD-2-Clause OR Apache-2.0), with raw termios via nix/rustix as the fallback.
**Implications.** Full license compliance with no capability loss for this design (custom bauds, modem lines, concurrent async I/O). A smaller ecosystem than serialport's, mitigated by the fallback being plain POSIX. Port enumeration is not depended on at all — the resolver reads `/dev/serial/by-id` directly, which turned out cleaner anyway (§12).

### 15.2 Edges terminate on endpoints, not nodes

**Problem.** The original sketch connected edges to nodes, but a demultiplexer's outgoing edges each carry a *different* stream: "which channel" had nowhere to live except ad-hoc edge attributes.
**Decision.** Nodes expose typed endpoints; edges join endpoints. Channels are endpoints with identities.
**Implications.** Channel selection is structural, not annotational; configuration addressing (`node/channel`) falls out; every later mechanism — facing, locks, binding — attaches to endpoints. This decision is upstream of nearly everything else in the design.

### 15.3 Orientation: from global rules to local typing, and the target/host anchor

**Problem.** The sketch encoded direction as global constraints ("file writers can only be downstream") plus the unintuitive note that data flows both ways along directed edges. Global rules are hard to validate locally, and the original naming candidates ("hardware-facing"/"user-facing") were factually wrong for three configurations the design itself requires: a TCP socket as the targetward extremity on the receiving machine, a physical serial port used on the host side, and a simulated target behind a PTY with no hardware at all.
**Decision.** Orientation is a local, per-endpoint property — faces target or faces host, with "faces" meaning looks-toward — anchored on the *system under control* rather than on silicon. An edge always joins one of each. Upstream/downstream survive as informal synonyms for targetward/hostward. Flow-connoting names (source/sink, producer/consumer, input/output) were explicitly rejected because bidirectional flow on an oriented edge is the whole point.
**Implications.** The original global rules become derivable facts about node types; validation is per-edge; dual-role nodes need one `faces` attribute; symmetric bridging configurations require the operator to declare a target, documented as a labeling judgment. Residual hazards: "host" collides with socket addressing (schema uses `address`, never `host`), and "target" collides with graph-theory edge terminology (edges reference two endpoints; the words source/target never appear in the schema).

### 15.4 Fan-out without tee nodes; the one-producer invariant

**Problem.** With 1:1 endpoint-edge binding, fan-out required explicit tee nodes, and the DAG admitted a silent failure: a diamond — one stream fanned through two paths that reconverge — duplicates hostward delivery and, worse, doubles targetward writes into the device.
**Decision.** Host-facing endpoints accept any number of edges (broadcast hostward, arbitrate targetward); target-facing endpoints accept exactly one.
**Implications.** Tee nodes vanish from configurations. The one-producer invariant makes unrestricted reading safe by construction, and accidental duplication becomes unrepresentable rather than merely lintable — validation shrinks to three checks. The cost: implicit merging of two streams into one consumer is also unrepresentable, deliberately; merging must be an explicit framing node (deferred, §14). The write lock acquired a natural, universal scope in the same stroke (15.7).

### 15.5 Boundary-only policy and the directional asymmetry

**Problem.** The sketch was silent on backpressure. A stalled PTY, socket, file, or outbound port must not stall serial ingest, yet dropping device *commands* is worse than delaying them; and 3-wire UART offers no flow control toward the host, so end-to-end backpressure hostward is physically impossible.
**Decision.** Interior nodes are queue-free and policy-free (parser state and a one-chunk holdover excepted); all policy lives at the four boundary types — a set that review expanded beyond the sketch's sockets-and-files to include PTY masters and serial ports in both directions. Hostward flow is lossy at boundaries with counters; targetward flow returns Accepted/Busy and backpressures to the origin, whose own kernel object buffers via native flow control.
**Implications.** No hidden latency, no unbounded memory, no tuning knobs in the interior; a single-threaded data plane suffices. Loss is always located, counted, and attributable. Kernel-level flow control, where configured, extends across the graph for free. The pause machinery built here is reused wholesale by arbitration (15.7) and outage handling (15.9's faulted-and-wait), which is the design's main economy.

### 15.6 Idle serial ports: gate reads or read-and-discard

**Problem.** The intuition "serial readers don't read unless something is connected" meets a kernel that buffers a few KB and then drops on overrun regardless — so not reading merely relocates the loss and greets the first consumer with a stale burst followed by a gap, mid-maintenance.
**Decision.** A configured serial node holds its port open (exclusivity; deterministic DTR against auto-reset adapters) and reads continuously, discarding with counters when nothing is attached.
**Implications.** Consumers always start on fresh data; loss is visible in state alongside driver overrun counters rather than silent in the kernel; the port is continuously owned. The polling-cost intuition was also corrected on the record: the expensive thing about polling is latency, never CPU. A replay ring for attach-time history became a clean opt-in future feature rather than an accidental side effect (§14).

### 15.7 Write arbitration: exclusive locks, write modes, and the stale-command hazard

**Problem.** Multiple writers to one console interleave at arbitrary chunk boundaries and corrupt protocols; the design's own use case puts writers on two machines. Additionally, byte streams offer no side channel through which a client could request exclusivity.
**Decision.** An exclusive write lock per host-facing endpoint, gating the existing pause machinery; reading is never arbitrated. Per-edge write modes `never`/`on-demand`/`held`; out-of-band acquisition via the control plane with an atomic `send` verb; purge-on-acquire and purge-on-detach as defaults; steal, lease, and detach-release for lifecycle; `free-for-all` retained as a per-endpoint opt-out; cross-machine exclusion by lock nesting with backpressure across the leg.
**Implications.** Arbitration costs no new data path. Correct scripts lose nothing to purging by construction; the 3-a.m. stale `reboot` cannot fire. The demux's `held` lock makes raw injection into a muxed port an explicit steal that stalls channels — the model telling the truth about the wire. Known limits are documented rather than hidden: origins are endpoints, not processes, and remote contenders block instead of failing fast until lock-forwarding frames ship (§9, §14).

### 15.8 Configuration versus state; operators own the graph

**Problem.** The sketch mixed desired settings with observed facts in one attribute list — baud rate beside "current log file" — which poisons round-tripping, and left unspecified what a missing device does to the graph.
**Decision.** A strict configuration/state split, enforced by schema, with the invariant: operators own the graph; the environment owns only state. Configuration operations fail only on structural invalidity; environmental failure faults nodes without removing them, generalized from serial ports to every boundary type as faulted-and-wait.
**Implications.** `dump` round-trips by construction and is the backup and migration story. Restart, replug, and first boot collapse into one code path. Every "what happens when X breaks" question in later design rounds had a one-word answer — faulted — which is the second major economy of the design.

### 15.9 Load semantics and the persistence gap

**Problem.** Applying a full configuration to a running graph requires diffing by stable identity; done naively it would HUP every PTY client and drop device bytes on every edit. And once running graphs are mutated incrementally instead, a daemon crash silently loses the surgery, because memory matches no file on disk.
**Decision.** Load is accepted only on an empty graph and is structurally atomic; running graphs change only via incremental verbs; diffing is deferred, explicitly, as future work. The daemon snapshots its configuration to a state file after every successful mutation; startup prefers the state file.
**Implications.** V1 avoids the hardest reconciliation code honestly rather than accidentally. The incremental verbs are promoted to core surface with defined cascade semantics. Full-file edits to a live system mean `--replace` and an accepted outage — a documented v1 cost. The state file makes crash recovery boring, at the price of the daemon owning a writable path.

### 15.10 Device identity and hotplug without libudev

**Problem.** `/dev/ttyUSB0` is not an identity: adapters return under different names, another adapter can squat on the old path, and a faulted node must recognize *its* device. Meanwhile the standard hotplug answer, libudev, is LGPL — excluded from linking by policy.
**Decision.** A resolver converts operator input to a structured canonical identity (`usb:vid:pid:serial:iface`) stored in configuration, resolving identity-to-path at every open and recheck via `/dev/serial/by-id` readlinks over a `<sys-root>/class/tty` fallback, so capture and resolution read one source and an identity minted where no by-id tree exists still resolves; fallback chain to topology identity and raw path; reappearance detected by cheap polling, with raw uevent netlink as a future Linux optimization. The ambiguity rule that guards the wrong-device case counts duplication over *devices*, never over by-id entries: udev derives the link name from `ID_SERIAL` plus the interface number — every component a function of the same fields that make an identity ambiguous — so two clones sharing a serial number collide on exactly one published link, and a link count can never exceed one for the hazard it was written to catch (review 32 `RES-1`). And the ambiguity rule binds **resolution as well as capture**: an identity two present devices answer to resolves to neither, so a node carrying it stays `waiting` rather than driving a coin-flip adapter. Capture degrading a duplicated serial to by-path does not make the check redundant on the other side, because three doors carry an ambiguous identity into resolution anyway — a configuration an older daemon persisted (`dump` wrote the string), a hand-typed identity, and the door no history fixes: an identity captured while one clone was plugged in, whose twin appears afterwards. Declining is the only arm available there, since identity-to-path resolution answers with a path and nothing else — "bind and warn" has nowhere to put the warning and would be indistinguishable, at every open and every recheck, from binding the right device. The cost is that the device listing now runs *before* the by-id readlink on the resolution path, because a by-id hit says nothing about uniqueness: 0.93 ms against 0.041 ms per resolution on this project's dev box (~110 tty entries), paid once per open and once per 1 Hz recheck per waiting node.
**Implications.** Configurations survive cold starts with hardware absent (identity-form never requires presence; raw-path input requires the device at add time, once). Wrong-device adoption is impossible by construction. Cheap-clone adapters degrade gracefully with documented instability. macOS needs only a resolver backend, not a design change (§14).

### 15.11 Codec pluggability and the envelope unification

**Problem.** Demultiplexing needs operator-supplied protocol knowledge, Rust has no sane runtime plugin story, and the licensing policy forbids linking existing (copyleft) protocol tools. Separately, wire-announced channels threatened the operators-own-the-graph invariant.
**Decision.** Compiled-in codecs behind an explicit registry and Cargo features, in their own workspace crates against a `serial_nexus_codec_api` crate; attributes as codec-validated opaque tables; an exec codec whose child-process envelope is *the same frame format* as the link codec's wire protocol; announced channels bind to configured identities, with `unbound` and `waiting` as state.
**Implications.** New codecs are a crate plus one registry line; external codecs are any-language processes testable through a pipe; copyleft tools run unmodified behind a documented, versioned, non-linking interface. Dynamic wire channels became a state-visibility feature instead of a graph-mutation hazard. The cost of no dynamic loading is a recompile per new built-in codec — accepted.

### 15.12 Wire security posture and channel identity

**Problem.** Serial consoles are frequently root shells; an unauthenticated TCP listener is a footgun. And "labels" had been doing two jobs — configuration addressing and stream naming — while containing slashes from device paths.
**Decision.** Loopback-only by default with SSH (including streamlocal forwarding) as the security layer and `insecure_bind = true` as the named exception; a hello frame with magic, version, announcements, and capability bits; terminology split into operator-chosen node names and codec-scoped channel identities, with `node/channel` as display form; a small custom frame format over yamux, for the identity/hello/envelope semantics yamux would not carry.
**Implications.** V1 ships no crypto to get wrong and inherits SSH's authentication; remote binds require a visible, greppable confession. Protocol evolution has a doorway (capabilities) instead of a flag day. The path-escaping wart from the original sketch dissolved with the terminology.

### 15.13 Control plane and the Windows exclusion

**Problem.** The sketch had no control plane at all, yet every design round added verbs that need one — and lock acquisition (15.7) structurally requires out-of-band signaling. Separately, "Windows if it's free" needed an honest answer.
**Decision.** A Unix domain socket (path by privilege level, CLI-overridable) whose file permissions are the entire authorization model; hand-rolled JSON-RPC 2.0 over newline-delimited JSON, batches rejected, notifications powering `subscribe`. Windows declared out of scope, with a large redesign accepted as the price of ever changing that.
**Implications.** One page of serde types instead of a framework dependency; concurrent CLI clients and streaming state observation from day one; everything debuggable with socat and jq. The Windows exclusion deleted an interprocess-abstraction layer and kept the PTY story purely POSIX — the honest answer was that it was never going to be free.

### 15.14 The PTY is not a serial port

**Problem.** PTYs differ from serial ports in ways that corrupt data or mislead operators: fresh PTYs echo and translate newlines (feedback loops the moment data reflects); client tcsetattr calls change nothing on real hardware and are invisible without an obscure mechanism (TIOCPKT alone does not report baud changes); break and modem lines don't traverse a PTY; there is no un-HUP event, so a silently watching client is indistinguishable from an absent one; and `/dev/pts/N` allocation is unstable across restarts.
**Decision.** Baseline raw + echo-off + EXTPROC at creation, reasserted on last close; packet mode plus EXTPROC to *observe* client termios as state, with a slow reconciliation poll as backstop, and propagation to hardware deferred behind an already-available subscribe-plus-RPC experiment path; break and modem signals as control-plane verbs on the serial node; presence-gated output (deliver when a client holds the slave, discard with counters when not) with attach detection via tcsetattr packets plus a sub-second HUP check; a configured symlink with owner/mode as configuration and the pts target as state, including the stale-dangling-symlink recovery rule.
**Implications.** Feedback loops are impossible by default; every client session starts deterministic; the semantic gap between PTY and port is *reported* honestly rather than papered over, and the propagation question will be decided from observed data rather than speculation. The mechanism's one exotic flag (EXTPROC) is flagged for early verification in implementation, with the poll path as the safety net — and as the whole mechanism on macOS if needed.

### 15.15 Protocol agnosticism: the framing is a module

**Problem.** Ratifying custom-frames-over-yamux (15.12) raised the opposite risk: v1 frame details ossifying into the design. Review found two live cascades. The exec envelope and the wire framing had been specified as one thing, so evolving the wire would have broken external codec processes that depend on envelope stability; and the targetward no-drop guarantee was implicitly resting on whole-connection TCP backpressure — a property of this particular framing, not of the design.
**Decision.** The design constrains the protocol and otherwise stays out of it, with one sanctioned exception: design aspects that exist to admit some form of protocol (identity-keyed channels, the event vocabulary, Accepted/Busy as a flow-control hook, binding states, capability-conditional features). The constraints are the six-clause contract of §9 — identity-addressed channel multiplexing, event-vocabulary transport with evolvability to control events, announcements, bounded frame size, no-drop targetward with flow control at least at connection scope, and version/capability negotiation with clean refusal. The envelope and the wire become two separately versioned contracts that happen to share one v1 implementation.
**Implications.** Substrate swaps (yamux) are contained changes rather than redesigns. Head-of-line blocking on targetward flow is documented as a v1 protocol property, bounded to human-scale command traffic, with per-channel flow control admissible without design change. External codec stability survives wire evolution by construction. §9 is restructured into contract plus v1 implementation, and future protocol work has an explicit conformance checklist.

### 15.16 CLI shape is presentation, not contract

**Problem.** The CLI's shape — subcommands and their names, argument names, output format — is expected to iterate as humans and AI agents use the tool and report back. The draft's phrasing ("a thin client mapping one verb to one RPC") quietly coupled the surfaces: taken literally, renaming a subcommand or regrouping the hierarchy would imply daemon-side changes, and any human-readable formatting in the daemon would have frozen presentation into the contract.
**Decision.** The 15.15 principle applied one layer up: the daemon constrains the CLI only through the RPC surface and otherwise stays out of it. `serial-nexus-daemon` exposes semantic operations returning structured JSON; all rendering lives in `serial-nexus-ctl`; CLI shape may rename, regroup, and compose RPCs freely. Two stability tiers: the RPC surface evolves deliberately and additively where possible, the CLI shape freely.
**Implications.** CLI iterations ship without daemon releases and without breaking scripts or agents pinned to the RPC surface. AI agents get two supported entry points — the CLI (with a near-free raw JSON mode) or the socket directly. Version skew degrades gracefully via JSON-RPC's method-not-found. The §10 verb list documents semantics, not spellings, and the usage examples elsewhere in this document (§6, §7.3) are illustrative spellings of the day, not commitments.

### 15.17 Capability probing and the no-target hardware doctrine

**Problem.** serial_nexus must support several systems — a Linux kernel and distribution spread plus macOS — and the original plan verified kernel assumptions through one-off spike binaries: unscalable across a support matrix, useless to end users on unlisted systems, and silent about environment problems. Separately, hardware-dependent tests implicitly assumed a real target device, which contributors and CI rarely have.
**Decision.** Consolidate every probe into `serial-nexus-doctor`, a shipping diagnostic crate that emits a copy-pasteable Markdown report (JSON for CI) covering kernel behaviors, environment, and — where adapters are visible — tiered hardware exercises. Adopt the no-target doctrine: Tier 1 is a dangling converter (identity, exclusivity, lifecycle, replug); Tier 2 is one converter with TX jumpered to RX (real driver data path, overrun behavior); Tier 3 is two converters cross-wired as a null modem (independent clocks, so baud accuracy, framing/parity error observation, break reception, modem lines — and the §4 symmetric configuration in physical form). Probes that transmit require the port to be explicitly named, since a listed port could be wired to live equipment.
**Implications.** Verification runs identically on every supported system and on strangers' machines, and support requests start from a uniform report. A single-port loopback cannot detect baud inaccuracy — TX and RX share one clock — which is precisely why Tier 3 exists. The daemon's runtime behavior stays independent of probing, so the doctor can be wrong without the data plane being wrong. The implementation plan's spikes crate is superseded, and release gates reference tiers, never ownership of a target device.

### 15.18 Readiness for tty descriptors: poll(2), not epoll

**Problem.** During the phase 2 data-plane build, `tokio::io::unix::AsyncFd` (epoll-backed) spuriously and persistently reported a pty master readable once a client attached: `read(2)` returned EAGAIN and a direct `poll(2)` reported no readiness while epoll insisted otherwise, and because the ready future completed synchronously the loop never yielded — starving the entire current-thread runtime and freezing the control plane with it. Reproduced in isolation and eliminated against packet mode, fd sharing, and select-loop structure: a genuine epoll/pty quirk external to serial_nexus, but one the architecture must answer.
**Decision.** Tty-family descriptors — pty masters and serial ports — are driven by non-blocking `poll(2)` readiness plus a short idle sleep (5 ms initially), re-polling immediately during active transfer so the interval bounds idle latency, never throughput. `AsyncFd` is prohibited for pty masters. The doctrine is scoped: socket boundaries (the control socket today, phase 6 legs later) use the runtime's native socket types, which do not share the quirk. The same implementation round folded three sibling amendments into their sections — §13 (serial2-tokio dropped for lack of an fd accessor), §7.2 (slave priming, since a never-opened master reports no HUP), §5 (holdover flush on writability, caught by a property test) — plus §3's `/` exclusion for names and identities.
**Implications.** The mechanism-level cost is idle wakeups: roughly 1% CPU per idle tty fd as built — negligible for one port, unacceptable at a lab box's fan-out — so phase 3's benchmark gains an idle-CPU-versus-fd-count axis with a stated budget, and exceeding it selects between the named escape hatches (adaptive idle backoff after quiescence, or `spawn_blocking` reader threads for high-baud ports) rather than reopening the epoll question. A future maintainer refactoring toward the idiomatic `AsyncFd` pattern will reintroduce a control-plane freeze; this entry exists so that refactor dies in review. *(Superseded in part by §15.19: the phase 3 benchmark falsified the "never throughput" claim for cross-process peers and selected the reserved thread escape hatch. Probe P8 later measured the underlying fact on a real kernel: a bare level-triggered epoll registration on a pty master agrees with `poll(2)` there — the starvation this entry records is a property of the async runtime's readiness-guard lifecycle, not of `epoll_ctl` in isolation. That does not reopen the question; it is written here so the next "just try AsyncFd" reads the mechanism before repeating the experiment.)*

### 15.19 The benchmark cashed the escape hatch: a hybrid data plane

**Problem.** §15.18's readiness model claimed the idle interval bounds "idle latency, never throughput," on the intuition that an active transfer re-polls immediately. The phase 3 benchmark falsified that for the case that matters: a peer in a *separate process* on a current-thread runtime. After draining to WouldBlock there is no other runnable task, so yielding returns instantly without letting wall-clock pass and the peer never refills the buffer; every cycle must therefore sleep, paying tokio's roughly one-millisecond timer floor per kernel-buffer refill. Hostward throughput capped near 1 MB/s (measured 1.2 MiB/s serial→log) — an outright failure of the ten-times-over-eight-ports bar.
**Decision.** Exactly the hatch §15.18 reserved, selected by the benchmark it named. The two high-rate hostward paths — the serial reader and the PTY master writer — moved to dedicated blocking threads parked in blocking `poll(2)`, which the kernel wakes the instant the fd is ready and which cost nothing while parked. The PTY writer is fed through a bounded bridge whose overflow drops are counted at that boundary, preserving §5's accounting; cross-thread counters became atomics. Low-rate paths (targetward flow, presence and termios polling) stay on the async thread under an adaptive active-to-idle backoff — so both of §15.18's named hatches were used, threads for hot paths and backoff for cold ones.
**Implications.** Measured: about 185 MiB/s lossless hostward; idle cost about 0.06% per polled fd (2% total at 32 idle PTYs, under budget) and zero for parked threads — §15.18's idle-CPU concern is closed by measurement, not hope. §15.18's "never throughput" phrasing is corrected here rather than rewritten there. The deliver contract survives untouched because it was context-agnostic all along: later codec transforms (phase 5) simply execute the synchronous hostward chain on the originating boundary's thread. What §5 retires is the single-thread *claim*; what it keeps is the discipline that justified it — single-writer-per-state, now enforced per thread with atomics at the seams.

### 15.20 Waiting verbs: the two-lane control plane

**Problem.** Phase 4's remaining surface — `send`'s acquire-with-timeout, `lock --wait`, leases — requires verbs that *wait*, and `Daemon::dispatch` was synchronous by design: that synchrony was the entire mechanism behind §10's "mutations are serialized." The obvious alternatives each break an existing commitment. Client-side retry polling breaks §6's promise that `send` is one atomic daemon-side operation and reopens the crash-while-holding window it exists to close; a bare notify-and-race wakeup breaks §6's promise that state reports *waiters*, and is unfair besides; making dispatch fully asynchronous dissolves the serialization invariant. Slice A also settled an ambiguity §6 had left open: whether `lock` names the origin or the endpoint.
**Decision.** A two-lane control plane. Every state transition remains a synchronous critical section on the runtime thread; a verb that cannot complete immediately registers in an explicit FIFO waiter queue on the lock and suspends holding nothing — no borrows, no locks, only its queue position — then re-attempts inside a fresh critical section when woken. Grants pass to the queue head on release, detach-release, lease expiry, and a stealer's release; steal bypasses the queue without destroying it; every grant, immediate or queued, runs purge-on-acquire first. Waiting is cancel-safe: a deadline, a dropped control connection, teardown, or removal of the endpoint dequeues the waiter with a defined error. Leases are grant-generation-guarded so a stale timer can never release a later grant. Addressing is ratified as built: `lock`/`unlock` name the *origin*, resolved to its unique host-facing endpoint by §4's single-edge rule; `send` names the *endpoint*, the CLI acting as its own transient origin.
**Implications.** §10's serialization claim is restated, not weakened: serialization was never "dispatch is synchronous" but "transitions are critical sections," and the two-lane model preserves that by construction. The review tripwire, with the same status as §15.18's AsyncFd rule: a `RefCell` borrow must never cross an `.await`. Exclusive-by-default carries a now-documented consequence — even a sole on-demand origin must acquire before writing, with `free-for-all` as the ceremony-free opt-out for single-console use. And one honest limitation joins §6's list: poll-sampled presence cannot see a close-and-reopen inside one poll interval, so a successor client can inherit a lock on the detach-release path; cross-endpoint exclusion and explicit unlock are unaffected, and the per-open generation epoch that would close it is deferred (§14).

### 15.21 The rig is a fixture, so the doctor certifies it

**Problem.** The tiered checklist (§15.17) rests on physical rigs — a jumpered port, a cross-wired pair — that can themselves be miswired: half-crossed TX/RX, a floating ground, the wrong ports paired. A Tier 2 or Tier 3 failure would then be unattributable — serial_nexus bug, or loose jumper? — and the plan's auto-detect sentence ("transmit a nonce, listen everywhere") had no defined verdict, no defined role.
**Decision.** Rig discovery and characterization become a first-class doctor probe, P5, opt-in like every TX-emitting probe. Discovery classifies each named port as dangling, loopback, or paired — pairs verified in both directions, so half-crossed wiring is reported by name. Characterization produces the *rig certificate*: data integrity across a rate ladder including a nonstandard rate (on a pair, independent clocks make this a genuine baud-accuracy check), deliberate baud and parity mismatches proving the error counters observable, break reception, and a modem-line map — where "not wired" is a valid answer, reported rather than assumed. Ports are named by resolver identity so the certificate survives device renumbering. The boundary is explicit: the doctor certifies the rig and stops; end-to-end rig exercises remain checklist items whose precondition is a clean certificate.
**Implications.** Every tiered checklist run starts from a certificate, so a tier failure is attributable before any serial_nexus code is suspected — phase 1's calibrate-the-judges principle extended to hardware. Discovery and classification are CI-testable against sim-built loopbacks and crossed pairs, with characterization reporting skipped on non-UARTs, so P5's logic never waits for a bench. P5 lands in phase 7, ahead of the first (0.1.0) checklist run, and the checklist gains its own negative control: pull one wire, re-run P5, watch the asymmetry get named. *(Amended after review 26.)* A precondition has to be able to fail: P5's verdict folds the certificate's own failures in rather than being computed from discovery alone, and it separates the two consequences — a *data-integrity* failure means the rig did not deliver the bytes it was handed, which is a stop condition before any tier (`unsupported`), while an uncharacterized item (break, custom baud, observable error counters) leaves a rig that works but is not fully characterized (`degraded`, named). Before that, the certificate reported its failures in prose the verdict never saw, so the precondition every tiered run starts from could not fail. *(Annotated after review 37, 37-TOOL-3, disposition **justify**, implementation-notes §3.23.)* **The shipped certificate is narrower than the Decision paragraph above, deliberately, and the paragraph is not being rewritten to hide it.** What P5 certifies today: per port, custom-baud acceptance, break **assertion** (`set_break(true)`/`set_break(false)` accepted on a port the doctor holds open alone), `TIOCGICOUNT` availability, and a raw modem-line read printed but folded into no verdict; per verified pair, a rate ladder at 9600, 115200 and a nonstandard rate in *both* directions, and one deliberate **baud** mismatch (115200 transmitting into a 9600 receiver) that must corrupt the pattern *and* raise the receiver's frame counter. Three items this section names are **not** in it: the **parity** mismatch (`p5_certify_pair` runs `Parity::None` throughout — only baud is mismatched), break **reception**, and far-side **modem-line signalling** (every modem read happens with the peer port closed, so it cannot answer what the wire carries). Those three are not lost: they are checklist items the certificate is the precondition *for*, and the in-tree guard for the break clause is `p12_serial_exclusivity::a_break_straddled_by_a_replace_leaves_the_line_transmitting`, which needs a rig the harness can see (`crossover_ports()` — `SNX_CROSSOVER_A`/`_B` on Linux). The boundary in the Decision paragraph is what makes the narrowing coherent rather than a gap: the doctor certifies the rig and stops, and an item that requires *driving* the pair through the design's own code was never the certificate's to run.

### 15.22 The exec codec is a boundary, and the empty channel is the multiplexed side

**Problem.** The exec node reads like an interior transform, but a child's stdin and stdout are kernel pipes with finite buffers and an independent consumer — §3's boundary test, verbatim. Treating them as interior produced the phase 5 audit's critical finding: one `select!` coupling stdin-write with stdout-read, so under sustained flow the child filled its stdout pipe and blocked on stdin while the daemon blocked writing it — a clean mutual deadlock. Separately, the envelope needed an identity for the multiplexed (raw device-side) stream.
**Decision.** The exec codec is a child-pipe *boundary pair*. Its two directions are pumped as concurrently-polled futures — a blocked write must never starve the read — with stderr as a third pumped stream into diagnostics and teardown-versus-crash as a discriminated outcome rather than a heuristic. The multiplexed side travels on the reserved *empty* channel identity, which configuration validation independently forbids for real channels, so the reservation cannot collide.
**Implications.** The boundary taxonomy in §3/§5 gains child stdio pipes. The concurrent-pump rule is a review tripwire with a regression guard (the 256 KiB round-trip in the exec crash test); any future subprocess integration inherits both rules for free.

### 15.23 Endpoint-keyed wiring, held-priority reclaim, and resync scoping

**Problem.** The codec node is the first with more than two endpoints, and the node-keyed runtime wiring could not express it. Building it surfaced two semantic gaps: §6's grants-to-the-queue-head rule let an on-demand `--wait` waiter inherit a stolen demultiplexer's `held` lock — corrupting framing *by design* — and §8's one-shared-frame-format promise left resynchronization semantics undefined across its two users.
**Decision.** The runtime wiring is keyed by endpoint address: every host-facing endpoint owns its lock, its fan-out, and one arbitrated targetward channel; every target-facing endpoint is a single-producer consumer that may write back. New node shapes plug in through their declared shape alone — the phase 6 leg landed with zero wiring changes, proving the seam. §6 gains held-priority reclaim: when the lock frees, a `held` origin reclaims ahead of the FIFO queue, because "held indefinitely" was always the promise. Resynchronization is scoped per user: the reference codec resyncs by length-guidance (skip exactly the framed length, count one framing error; only a mangled length prefix is unrecoverable), while the link codec, on a reliable transport, treats any violation as a protocol error and never resyncs.
**Implications.** FIFO fairness is restated as "FIFO among on-demand contenders, beneath held reclaim" — a correction to §6 as previously written. One frame format still serves both contracts (§15.15) because resync is a user policy, not a format property. Standalone re-multiplexing instances load and wait for a driver, recorded as deferred work (§14).

### 15.24 The leg: hello as a distinct construct, and fragmentation, never drop

**Problem.** The wire needed its handshake without touching the frozen envelope golden vectors. The phase 6 audit then found a critical §5/§9 violation: an oversize chunk — the uncapped `send` line, or an exec node's raw device stream — hit the frame bound's encode error and was silently dropped, uncounted (reachable because the read buffer equals the frame bound). A second wedge: a `faces = target` leg whose local producers all reported `Active` forever while its independent read direction died with the pump.
**Decision.** The hello is a distinct wire construct, not a fifth event kind: it reuses the length prefix, opens with the magic, and validates magic and version before any version-specific field, so a mismatch always refuses *as* a mismatch; the wire version and the envelope version are independent, cashing §15.15's two-contract split; capabilities are a bitset with lock-relay reserved. §9's frame-size clause is completed: a chunk exceeding the bound is fragmented across consecutive data frames, never rejected, never dropped. A leg's two directions are independent — exhaustion of one parks that half and never tears down the wire. The handshake runs under one overall deadline, so a trickling peer cannot wedge a listener.
**Implications.** Golden vectors stay byte-frozen across wire evolution. Fragmentation is contract text now, with a 100 001-byte `send` round-trip as its regression guard. Purge-on-reconnect, binding backpressure for `waiting` channels, and disconnect-release for the leg's implicit on-demand origin all landed exactly as §§6–8 specified — this audit's role was alignment, not invention.

### 15.25 Phase 7: identity by construction, and the state file finds its home

**Problem.** Phase 7 had to make the resolver, the reopen ritual, and the state file real — and three specifications were looser than the code needed. §12's identity model didn't say what happens when two adapters share a *non-empty* serial; §11 named a state file but not its path, its trigger set, or its shutdown semantics; and the incremental-verb list assumed all five verbs would ship together.
**Decision.** The resolver became a shared, dependency-free `serial_nexus_core` module (the doctor's P4 sysfs walk, promoted) rooted by `dev_root` so one flag selects a self-contained fixture tree. Its two directions are asymmetric by rule: path-form and bare-serial input require device presence at add time; identity-form input never does. A `usb:` identity resolves only to a device whose sysfs identity matches exactly — squatter refusal by construction rather than by comparison code — and both absent *and duplicated* non-empty serials degrade to by-path with the documented warning. The reopen ritual runs off one async supervisor per serial node, woken by the blocking reader's loss `Notify`, polling for the same identity, reapplying termios, `TIOCEXCL`, and configured modem lines; purge-on-reconnect drains the parked targetward channel with a counter — the one sanctioned targetward drain, and the third instance of §6's purge invariant. The state file is socket-adjacent by default (`<socket-stem>.state.toml`), written atomically after config-mutating verbs only; `--state-file` buys reboot durability; shutdown preserves, the `teardown` verb persists emptiness. `connect`/`disconnect`/`set-attribute` are deferred (§14): `add-node`, `remove-node --cascade`, and `load --replace` cover the operational need without live edge surgery.
**Implications.** The whole §12 matrix runs unprivileged against fixture trees, and the audit's worst find — `remove-node --cascade` of a lock-holding writer leaving a phantom holder wedging the endpoint — is now a regression test, alongside duplicate-serial degradation and empty-input rejection. The physical Tier-3 rig later validated every behavior here on real silicon, including a live unplug/replug with an exact `purged_on_reconnect` count; the one genuine hardware bug of the entire project was in the *doctor's* pair certification (a missing post-open baud settle), on a path the sim structurally skips — a lesson §16 generalizes.

### 15.26 Out-of-tree codecs: embed the daemon, don't load plugins

**Problem.** Some codecs cannot live in this repository — protocol terms, licensing, or ownership put them out of tree — and they need a stable open core to build against. Three routes existed: runtime plugin loading, exec-only, or source-level composition. Dynamic loading stays rejected on §15.11's grounds — Rust has no stable ABI, and a `dlopen` surface would turn every internal type into a compatibility promise. Exec-only works today for any language but taxes Rust authors with a child process, an envelope round-trip, and process supervision they don't need.
**Decision.** Source-level composition, made cheap. The daemon splits into a `serial_nexus_daemon` library plus a thin `serial-nexus-daemon` binary; the codec registry becomes a value — `Registry::with_builtins().register(name, factory)` — rather than a match statement; name collisions fail at startup. The supported extension surface is exactly two semver'd contracts: `serial_nexus_codec_api` (the codec trait, attribute tables, envelope types) and the narrow `serial_nexus_daemon` entry API (run options, registry, version constants); everything else stays private. A new `info` RPC reports registered codec names and protocol versions, and unknown-codec configuration errors carry the available list. An in-tree external-consumer template — a trivial codec crate plus a dozen-line custom daemon, workspace-excluded, built by CI from the consumer's position — proves the pattern compiles on every push. Both codec forms get conformance kits: `serial_nexus_codec_api` grows a `test-support` feature (generic suites any `Codec` implementation instantiates in its own tests: resync termination, bounded parser state, mux↔demux round-trip identity, fragmentation tolerance), and `serial-nexus-sim` grows an exec-conformance mode (the golden vectors plus sustained full-duplex liveness — the §15.22 deadlock class as a test — oversize handling, and crash-restart cleanliness).
**Implications.** An out-of-tree repository pins this one by version tag and inherits everything by linking: the CLI, the sim, the doctor, and the validation scripts all work against a custom daemon unchanged, because §15.16 made the RPC surface the contract. The cost is a second, deliberately tiny stability surface — the entry API — guarded by the CI-built template rather than by promise. The exec path remains first-class for non-Rust and copyleft ecosystems, and its new harness closes the one bug class (pump coupling) that has actually bitten external-style codecs. Registry-as-value also quietly serves §16's simplification agenda: a table is easier to introspect, test, and extend than a match arm.

*(Amended after the review-26 remediation.)* "Everything else stays private" acquires one bounded exception: a crate whose parser accepts bytes from an untrusted peer may expose that parser through a module named `unstable_fuzz_api`, whose documentation disclaims stability in its first sentence and whose only sanctioned consumer is `fuzz/`. The trade was weighed against the alternative — extracting each parser into its own crate — and the exception won on the grounds that this boundary exists to stop internal churn from breaking an *embedder*, not as an end in itself, and a module named and documented this way cannot be depended on by accident. Two parsers qualify today: the daemon's control-socket line framer, which frames every byte before any verb is dispatched, and the web console's HTTP head parser, which §15.29 permits to face a network and which runs before the token gate. The rule that keeps this from eroding is mechanical: an item re-exported there must have a fuzz target driving it. Recorded with its reasoning in `docs/implementation-notes.md` §3.19.

### 15.27 The review round: invariants move into the places that can enforce them

**Problem.** A 27-reviewer adversarial code review (56 verified findings) confirmed §16's thesis with uncomfortable precision. Its worst finding was the *third* recurrence of the same bug — a targetward framer skipping an oversize chunk on encode error, fixed in the leg, fixed in the exec node, missed in the in-process codec — and its next tier showed invariants true only by luck or phrasing: held-priority reclaim won by tokio scheduling rather than by rule; `snapshot()` identified holders by label string; a whitespace-only sysfs serial minted a concrete `usb:` identity, reopening the wrong-device hole §15.10 promises is closed by construction; and a stalled-but-present PTY client could wedge daemon teardown on an unbounded join.
**Decision.** Every fix moved an invariant into the layer that can enforce it. Fragmentation became a shared helper plus a §5 per-writer obligation with a residual counter. Held priority moved into `lock::acquire` itself — denied while a held origin is registered — property-tested in the pure state machine. Identity fields gained a spelling rule (`-` for absent; empty is malformed; whitespace normalizes to absent) enforced at the source. The PTY writer observes `stop` inside its poll loop — the fd-safe fix, chosen over the review's bounded-join-and-detach suggestion, which would have closed a raw fd under a live thread. Hostile-input bounds landed on the control-socket request line and exec stderr. Two review recommendations were deliberately declined with reasoning recorded: waiting-verb cancellation on request-half EOF is §15.20 behaving correctly (a half-close and a killed client are indistinguishable at read time), and a log node faulted by overflow deliberately keeps consuming.
**Implications.** No architectural change: every finding was a localized fix, and the pure `serial_nexus_core` state machines survived 27 reviewers with zero new defects — the property-test investment paying out exactly where it was placed. The one on-upgrade behavior change (retired empty-field identities coming up `waiting`) is safe and documented in §12. The review's meta-lesson is §16.1 vindicated in the negative: the misses clustered exactly where an invariant was still upheld per node, by hand.

### 15.28 The web console: a tap, a ring, and a token — not a logger

**Problem.** Operators want a browser view: every console listed, one selected and shown live, a one-line send box. The obvious client-only design has the web server *add log nodes* to every console and tail the files — but that makes a viewer mutate the operator-owned graph (§8, §11), persists its plumbing into the state file and every `dump`, and couples *watching* a console to *writing its bytes to disk*. A spy-PTY variant shares the mutation problem and adds fd babysitting.
**Decision.** The web client is a pure RPC client (`serial-nexus-web`, its own crate and process; the daemon gains no HTTP). The daemon gains exactly two small, generally useful capabilities instead: the **tap** — a connection-scoped, read-only dynamic attachment at a host-facing endpoint, streaming hostward bytes as notifications with a bounded queue and counted drops, the `never` write mode in dynamic form — and the **replay ring** (§5), §14's deferral finally meeting its driver, giving attach-time scrollback with an exact critical-section splice. Input is the existing `send` verb; the console list and lock badges are `state` plus `subscribe`. Security keeps the leg posture plus one honest correction: a loopback TCP port is reachable by *every local user*, unlike the 0600 control socket, so the web server requires a per-session bearer token (printed as a ready-to-open URL, Jupyter-style) and validates the Host header; binding beyond loopback is refused, and remote access is SSH forwarding, as everywhere else in this design. *(Bind policy revised by §15.29: TLS-plus-token became the sanctioned non-loopback mode, with a token-mandatory insecure escape for trusted networks.)*
**Implications.** Watching a console never touches the graph, the disk, or other viewers; a slow browser tab costs only its own tap's counters. The tap and ring serve more than the web — `serial-nexus-ctl watch` falls out nearly free. The declined log-based design is recorded here so it is not re-proposed as a simplification: logging remains available to any operator who wants it — the web UI shows lock holders and can suggest `replay_ring` where history is off — but recording is an operator decision, never a viewer's side effect.

### 15.29 Bearer tokens are not TLS: the web bind policy, revisited

**Problem.** §15.28 refused non-loopback web binds outright, and review of that stance raised the fair question: if every request requires a bearer token, isn't that equivalent to the API keys securing widely deployed services — making the loopback restriction redundant?
**Decision.** The equivalence is structurally right and operationally incomplete, and the gap is exactly TLS. API keys secure real services because they ride an encrypted channel; a bearer token over plaintext HTTP is a secret broadcast to every on-path observer, who reads it once and holds console access — root shells, per §9 — indefinitely. The token and the bind restriction therefore solve different layers: the token is authentication (*who may act*); loopback or TLS is transport (*who can read and replay*). On loopback the kernel is the channel, which is why token-plus-loopback needs no crypto. The policy becomes three tiers: loopback plus token by default; `--tls` (rustls) plus token as the sanctioned non-loopback mode — the point at which the API-key analogy genuinely holds; and `--insecure-bind` as the leg-precedent named footgun for operator-trusted networks, token still mandatory, forfeitures stated in the flag's own help text. Off loopback, Host validation covers the configured names and the token leaves the URL for a header after first exchange. The vessel it moves into is named for the listener that set it (`nexus_session_<bound port>`), because a cookie's jar key is (name, domain, path) and never the port (RFC 6265 §8.5): under one fixed name the two-console arrangement §17 prescribes — run two servers for two daemons — collided on a single jar entry, and opening the second bootstrap URL logged the operator out of the first with no recovery but a reload that 401s. Two things the analogy also imports were deliberately *not* adopted: widely deployed API services carry rotation, revocation, rate limiting, and a security team; this design keeps the single per-session token and prices network exposure accordingly.
**Implications.** The flat refusal was too rigid — the same "a named footgun beats a patched binary" reasoning that shaped §9 applies to the web surface — and the revised policy is both more honest and more useful: the default loses nothing, the TLS tier makes the user's analogy true instead of arguing with it, and the insecure tier documents its cost instead of pretending the demand doesn't exist. One asymmetry survives from §15.28: the browser surface still gets no *plaintext* sanctioned mode short of the loud flag, because it renders untrusted device output and carries the whole UI, not framed bytes. And the cookie vessel carries one cost the policy could narrow but not remove. Cookies are not port-scoped in *either* direction: the Origin check stops a sibling-port page from making this server act, but nothing stops the operator's browser from *sending* a cookie to some other service on another port of the same host — to the browser that is the same site, `HttpOnly` governs script rather than the browser, and `SameSite=Strict` is silent precisely because same-site is the case at hand. Since the token is shell-equivalent (§15.35: graph editing is daemon-user capability), the browser's credential is split in two rather than left whole: the token is scoped to the WebSocket upgrade path, and a separate, freshly minted asset credential worth nothing but this project's own published static assets carries the navigations and subresource loads, which can present nothing else. That turns what a rogue sibling-port service reads out of one ordinary navigation from console access into a file it could have downloaded from the repository. The residual is stated rather than implied: a page *served from* a sibling port is same-site, so it can fetch its own `/ws` with credentials and log what the browser attaches; ending the auto-replay entirely means taking the token out of cookies altogether, which no browser can do for the requests that must also be gated (review 32 `WEBS-1`, `docs/security.md`).

### 15.30 macOS contact: the baseline is a contract, the fd is a platform arm

**Problem.** The first hands-on macOS run found the PTY node type entirely non-functional — §7.2's baseline termios was applied through the master, which BSD rejects with ENOTTY — and both defects it surfaced *contradicted the predicted verdicts* in the platform notes, which had been written from cross-checks rather than hardware. macOS adds two pty facts of its own (a slave's termios resets to cooked on last close; a never-opened master reports no HUP, already covered by priming), and one test-infrastructure limit: a macOS pts cannot impersonate a serial device, because the platform baud ioctl rejects it.
**Decision.** The §7.2 baseline became explicitly a contract with platform arms: Linux applies and resets through the master; macOS applies through a momentarily opened slave and re-asserts on the presence rising edge, accepting a poll-latency window consistent with the platform's poll-only observation story. Doctor P2 gained a third verdict shape — `degraded` means the core presence signals hold and the design's platform arm carries the rest — instead of conflating "different mechanism" with "unsupported." (Sharpened later on the real Linux box: the discriminator is whether the master accepts termios — Linux yes, hence `supported`; BSD no, hence `degraded` — while never-opened-HUP absence is *universal* and priming handles it on every platform; the first fix briefly assumed Linux HUPs there, the §15.30 trap reintroduced by the §15.30 fix, until hardware corrected it.) The no-target doctrine's *fixture* leg is recorded as Linux-only: on macOS, serial-device tests self-skip in favor of the real-rig gate, which is §16.7 applied rather than violated. *(Extended when §7.2's last close grew its hostward flush.)* The flush opens the slave on **both** platforms — the master cannot name the whole queue on either — so it is the momentary-slave-open mechanism this section introduced, used a second time rather than a second mechanism. What stays a platform arm is only the *readability* of that fd: on Linux the baseline applied through the master survives the client's close, so the fd is already raw and a `tcsetattr` there would merely re-arm a `TIOCPKT_IOCTL` packet the flush exists to avoid creating; on BSD the pair has reset to cooked by then, and a canonical-mode read returns only complete lines, so the flush sets the pair raw first or a half-written line survives it into the next session.
**Implications.** The Linux path is byte-for-byte unchanged; macOS moved from cross-checked to runtime-verified at full test parity, byte-exact over a physical crossover. The deeper lesson repeats §16.7 with sharper teeth: *predicted* platform verdicts are not verified ones, and the two defects lived precisely in the gap between docs written from expectation and kernels consulted in person.

### 15.31 The validation suite becomes a crate

**Problem.** Fifty-eight bash validation scripts were the executable exit criteria — and nearly every one leaned on Linux-flavored tools (`stat -c`, `nc -q`, `sha256sum`, `timeout`, `/dev/serial/by-id`) that break on macOS, exactly when a second platform became real. The harness also duplicated an RPC client in jq and paid a lint stack (shellcheck, jq-lint, tested helpers) whose entire purpose was policing bash's footguns.
**Decision.** The suite is ported wholesale to `serial-nexus-itest`, a workspace test crate: an in-Rust JSON-RPC client, sim doubles orchestrated as subprocesses, structured assertions with SHA-256 byte-exactness, and provider functions (`serial_rig()`, `crossover_ports()`) that yield a platform-appropriate serial device or make the test self-skip visibly — the skip discipline as a library primitive. Three shell scripts survive where they genuinely wrap external tools; §16.11 schedules their absorption. The shellcheck and jq-lint gates retire with their subject matter.
**Implications.** One language, one assertion library, CI that is literally `cargo test --workspace` on both platforms, and the presence-is-not-readiness conventions carried over as sim gating flags rather than folklore. One deliberate non-simplification is recorded: sim doubles remain subprocesses, because cross-process scheduling realism is what exposed §15.19's timer floor, and an in-process double would have hidden it.

### 15.32 Default scrollback, and history that lives with the viewer

**Problem.** A console without scrollback punishes whoever arrives late — which is everyone the console exists for — yet the ring shipped opt-in, and per-channel rings on codec and leg endpoints were a scoped deferral; meanwhile browser history across reloads had no story at all, and naive re-replay would append ring-depth duplicates to any client-side log on every reconnect.
**Decision.** `replay_ring` defaults on (64 KiB) for every host-facing endpoint, opt-out with `0`, superseding both the opt-in default and the per-channel deferral; the cost — bounded memory plus one mirrored copy per chunk — is stated and re-benchmarked, and the audit's accounting doctrine (the mirror is a spy outside the graph; `discarded_unattached` never depends on it) becomes normative so the default cannot hide loss. For history, the tap protocol gains monotonic hostward byte offsets, replay gains `from_offset`, and `info` gains a per-boot instance nonce; the web client persists per-console history in the browser's Origin Private File System, keyed by socket path, endpoint, and instance, spliced exactly by offset. The viewer records for the viewer: §15.28's recording principle survives with the recording moved to the party who chose it. A stable default port follows necessarily — the storage origin includes the port — and eviction honesty is surfaced in the UI rather than assumed away. Two clauses of that retention story are load-bearing and easy to get wrong in opposite directions. Retention is bounded by *consoles*, not by daemon restarts: because a record's key folds in the per-boot `instance` nonce, a cap enforced only within a boot is not a cap at all — every restart orphans one full record per console, forever, until the origin's quota is reached and persistence dies for good — so the client sweeps every stored record that does not belong to the current origin and the current boot, once per connection, and the per-console cap becomes a bound on what accumulates rather than on what one boot retains. And a re-opened tap whose `from_offset` sits past the stored frontier *in the same epoch* is a real hole — the daemon's ring rotated over the bytes between while nobody was watching, which with the default 64 KiB ring is the ordinary outcome for a talkative console — so the client charges the lost byte count once and marks it ahead of the replay marker, which would otherwise positively assert a continuity that is false. The marking is a terminal annotation only: the stored and exported bytes stay a raw device log, because an export that interleaves the client's commentary with the device's output is no longer the thing an operator attaches to a bug report.
**Implications.** The web console is useful at first click with zero configuration; server-side logging remains purely an operator decision; and the offset protocol, added for the browser, incidentally gives every future tap consumer exact resumption semantics. The trade accepted with eyes open: default-on means the "costs nothing when unset" clause of the original ring is retired, replaced by a stated, bounded, benchmark-guarded cost.

### 15.33 The map node: console quirks belong in configuration

**Problem.** Every quirky UART — the console that emits bare LF, the boot ROM that wants CR, the firmware that backspaces with DEL — forces its correction into every consumer: picocom flags here, terminal settings there, a mangled log everywhere nobody remembered. The graph had no home for a per-console byte transform: codecs are framed and channeled, heavier than the job, and the quirk knowledge lived outside the daemon's configuration entirely.
**Decision.** A `map` node type (§7.8): one target-facing and one host-facing endpoint, two ordered mapping lists named by the direction of the bytes they transform — `hostward` (picocom's `--imap`) and `targetward` (`--omap`), with the flow-relative input/output names rejected on §15.3's standing grounds and the correspondence documented instead. The vocabulary is picocom's byte mappings plus its hex-display family; rules are stateless byte-to-sequence substitutions, first match wins, unknown names are structural, output is bounded at the largest active expansion factor so the holdover contract survives. The node is explicitly not a codec — no channels, no frames, no state — and its targetward edge defaults to `held` with steal-to-bypass as the sanctioned raw path: `send` at the map speaks mapped, `send` upstream after a steal speaks raw. Per-rule substitution counters land in state.
**Implications.** A console's peculiarities are written down once, in `dump`-able configuration, and every consumer — PTY, log, leg, tap, web — sees the corrected stream, including the default rings' pleasant side effect of a raw and a mapped scrollback coexisting. The node is also the first non-codec interior transform, and it slots into the endpoint-keyed wiring (§15.23) with zero new machinery — the model generalizing exactly as it was built to.

### 15.34 Review 26: the classes behind the findings become rules

**Problem.** The second comprehensive review surfaced 93 findings, and the worst clustered into four repeatable classes rather than 93 accidents: unvalidated numeric configuration (an absurd `replay_ring` was an allocation, not an error); scan-instead-of-parse at a trust boundary (the web bridge's verb screen could be smuggled past with a second request behind a newline); uncapped collections fed by remote input (the unbound-identity list, pre-authentication connections); and — for the fifth time — an invariant re-derived by hand where a shared helper existed to own it (purge-to-quiescence, write-mode promotion).
**Decision.** Each class becomes a normative rule where the next instance would be born. §11: every numeric attribute carries a stated maximum, range-checked structurally before anything is created, and unknown keys are refused naming the key. §17: the bridge *parses* each frame as exactly one request and forwards only an explicit allowlist — screening by structure, never by scanning. Remote-fed collections are capped with counted overflow as a standing pattern. The re-derivation class gets no new rule because §16.1 already is the rule; the fix moved `drain_to_quiescence`, `effective_write_mode` and the hostward fan-out into the shared layer where the earlier instances live. Two of those carry a binding clause the move alone does not state. The two configuration-to-runtime write-mode promotions are computed in one place that **both the validator and the wiring consult**, because a validator reasoning about declared modes while the runtime registers effective ones is a drift with no bound on its consequences — the reachable shape being two maps on one upstream endpoint with `write_mode` written nowhere, both promoted to `held`, one starved forever and invisible in `state`. And the hostward fan-out collapses into **one helper serving all five producers**, which charges the no-live-sink case to the producer's unattached counter *inside* the helper rather than trusting each caller to remember: the loop had been hand-rolled five times and only the serial copy counted consumer absence, which is exactly how the map shipped as the one producer that never did. A file refused by validation that parses to nothing joins the structural list too — a mis-typed `[[nodez]]` under `--replace` was an unannounced `teardown` reported as success. Alongside: `tap.closed` notifications so mutation never silently orphans an observer, the one-waiting-verb-per-connection rule closing a §15.20 pipelining gap, the codec-mux edge-mode corollary, the two-held refusal, `spchex` corrected against the upstream oracle, the serial output leg refused rather than accepted-and-inert, and unix leg sockets at 0600. Every finding's disposition — including the deliberate declines — lives in the remediation ledger, which exists so a declined item cannot be silently re-fixed.
**Implications.** The suite grew from 265 to 435 tests, and the fixes are contract text or shared code, not local patches. The meta-lesson is now three-for-three across reviews: findings cluster where a rule lived in prose instead of in a type, a cap, a parser, or a helper — and the remedy each time is relocation, not vigilance. *(Amended after the v12 audit.)* The verification rule this round established — a verifier gets the finding and the tree, never the report — needs a second clause of the same standing: **the tree must not move under the verifier.** The v12 audit followed the first rule and broke the second, fixing findings while the skeptics read, and 35 of 43 verdicts came back "not real" for defects that were real when filed and fixed by the time they were judged. A refutation of an already-fixed defect is not evidence; it is a different tree. Freeze the worktree for the verification pass, or pin the verifiers to the commit the finders read.

### 15.35 The graph opens up: enumeration, edge surgery, and the web editor

**Problem.** Operating the daemon still required knowing device paths out-of-band (`ports` didn't exist), reshaping a live graph still meant remove-and-re-add or a `--replace` outage (edge verbs were deferred), and the web console could observe everything but change nothing — a posture originally defended as a feature, revisited with a fair argument: a token holder already commands every configured console on the machine, so withholding graph edits protects little while costing real workflow.
**Decision.** Three surfaces. `ports`: passive resolver enumeration — identity, path, bound-status; never `open(2)`, because probing a port toggles DTR. `connect`/`disconnect` leave §14: an edge operation runs the same critical-section structural validation as load (orientation pairing, the single-edge rule, mux-edge write modes, held-origin uniqueness), a mid-stream connect joins the fan-out at the live edge, and a disconnect of a lock-holding origin releases and purges — the §15.27 phantom-holder lesson applied before the bug could recur; `set-attribute` alone stays deferred. And the web posture is settled: the bridge allowlist grows the graph-editing verbs, the never-mutates non-goal is superseded, and the capability statement is made where it belongs — graph editing is daemon-user capability (log nodes write files, exec codecs run commands), so the token is operator trust, stated in the security docs rather than implied. Lifecycle verbs stay off the browser wire: the ask was graph editing, and `shutdown` from a web page serves no one. The UI gains the graph page (live topology with status indicators) and the editor page (palette, edge surgery, confirmations that name what cascades).
**Implications.** The reference workflow finally closes its loop in one place: see what's plugged in, wire it, watch it, drive it, reshape it — with the §4 rules enforced by the daemon and merely *surfaced* by the UI, so the editor cannot construct what the model forbids. The earlier defense of the read-only bridge is recorded, not erased: it was the right default until the operator decided otherwise, and the decision — like every posture in this design — belongs to the operator.

### 15.36 The flake session: mechanisms, not mysteries

**Problem.** Four of six CI pushes failed on three different tests, and the investigation surfaced five distinct mechanisms plus one real product defect hiding beside a fixed one: a harness WebSocket client that abandoned partially-read frames on deadline expiry (guaranteed eventual desync against a never-idle 5 Hz stream); sim doubles that treated a level-triggered pty `POLLHUP` as terminal — or busy-spun a core on it; tests asserting byte-exactness across boundaries §5 *sanctions* as lossy; a presence gate narrower than the evidence already in the master (a collapsed termios-only session never released its lock); and a CI fuzz loop running a stale hand-kept list while a meta-gate asserted only that target *files* existed. Twice, the first regression guard proposed was demonstrated to pass against the unfixed defect.
**Decision.** Each mechanism becomes doctrine (plan §3): harness protocol clients are fill-then-commit — deadline expiry never consumes; sim doubles modeling stateless hardware tolerate hangup forever, pause rather than spin, and get their idle CPU asserted; completeness is asserted only where the design promises it, with explicit depth cited to §5/§15.19 where a test needs it, and the sim's verdict now distinguishes timeout from loss; the pty latch arms on any session evidence, with the node's own packet drained-and-counted and the no-evidence case recorded as the harmless, self-healing residue; CI loops enumerate from the tool and meta-gates assert *execution*, not existence. Two process rules got teeth: a regression guard is valid only with fail-first proof against the unfixed tree, and flake diagnoses receive independent adversarial verification before the fix ships — three of five such verifications materially corrected the diagnosis they reviewed. Probes P6–P11 (and, since §15.39, P12) replace kernel assumptions with measurements, and one residual load-sensitive failure is recorded as an open lead with its capture rule: never filter suite output before the failing name is saved.
**Implications.** "Flaky" is a symptom with a mechanism behind it; every mechanism found became a deterministic guard, and the two refuted guards are the reason fail-first proof is now mandatory rather than customary.

### 15.37 The browser half joins CI: Playwright over hand-rolled CDP

**Problem.** §16.7 left the web UI's browser half — the OPFS adapter, the `tap.closed` re-anchor, the editor flows — checklist-verified only, and the checklist does not run per push. The remedy had to drive a real Chromium headlessly, and the field offered three routes: Puppeteer, Playwright, or a Rust CDP crate keeping the harness one-language.
**Decision.** A pinned Playwright suite, Chromium project only, launched as a subprocess from a `serial-nexus-itest` gate test that self-skips without node — the same time-boxed concession §15.31 already made for `node --test`, never a build dependency. The research verdict was one-sided for the testing workload: Playwright is the current default for end-to-end suites, with auto-waiting and web-first assertions built to kill exactly the deadline-tuned waiting this project just spent a session debugging, while Puppeteer remains the leaner Chrome-scripting tool. The Rust-CDP route was declined on this project's own freshest evidence: §15.36's F1 was a hand-rolled protocol client desynchronizing under a deadline, and a hand-rolled CDP client is that risk again, wearing a bigger protocol. Traces are captured on failure, the browser and package versions are pinned, and the manual checklist shrinks to rendering fidelity and real-rig interaction.
**Implications.** The §16.7 "unverified" marker comes off the browser half; reload-splice, storage-badge, editor, and smuggling-refusal behavior are asserted where they actually run. The concession is bounded and named: one pinned npm dev-dependency tree, test-time only, self-skipping — and if the UI ever outgrows Chromium-only, the suite's runner already speaks the other engines.

### 15.38 The browser suite pays for itself: an epoch, and an ioctl on the way out

**Problem.** §15.37's Playwright suite was written to stop *asserting* the browser half from a distance. Its first green-to-red run produced three defects, and only one of them was in the browser. (1) The client's `offsetSpaceReset` inferred "the daemon restarted its offset space" from `from_offset < my frontier` — which is *also* exactly what an ordinary reload with a non-empty replay ring looks like, because a ring exists to re-send bytes the client already has. Every such reload was therefore declared a restart: the ring was re-rendered under a false "the graph was reconfigured" marker and the duplicate was written back to storage, so stored scrollback grew by one copy of the ring per reload (measured in Chromium: 19 → 38 → 57 bytes over three). Guessing the other way would have frozen the console instead; offsets alone cannot answer the question. (2) `load --replace` opened the replacement serial node's device *before* releasing the outgoing one's fd — `load` is one synchronous critical section (§15.20), and aborting the supervisor task does not drop the `Rc<SerialPort>` clone its future holds until the runtime gets the thread back — so the daemon EBUSY'd against itself. On a real FTDI port that is a one-second `faulted` flap during which an accepted `send` was acknowledged and then purged rather than written; §5 permits dropping hostward, never targetward. (3) On a pty-backed device the same collision is *permanent*, because `TIOCEXCL` lives on the tty and clears only at its last close, which a held master never reaches — and that permanence is how a one-second bug became visible at all.

**Decision.** The daemon stops leaving either question to inference. `tap.open` reports an **`epoch`**: an identity for the endpoint hub, and therefore for its offset space, unique within a daemon process and never reused. A client persists it beside its scrollback and re-anchors exactly when it changes, which closes the recorded open issue that `info.instance` — correctly per-*boot* — does not rotate when `load --replace`, `add-node` or `remove-node` rebuilds a hub. And `SerialNode::teardown` **releases `TIOCEXCL` before letting go of the port**: exclusivity is a claim the node made, so the node gives it back when it stops. The unclaimed window is bounded by the same critical section and the next opener re-takes it; a guaranteed outage is the worse trade. *(Both halves of D2 were generalized later, under review 32 — the rule now covers every tty-level assertion the node made rather than this one ioctl, and every exit path rather than `teardown` alone, including the reconnect ritual's own await window; §7.1 states it, because the port's lifetime is where it belongs.)* Pty-backed serial devices — socat `PTY,link=`, QEMU `-serial pty`, the project's own sim — go from permanently unrecoverable to working.

**Implications.** The suite's value was not the assertions it added but the ones it made *possible to fail*: two of the three defects live below the browser and had been shipping through a green suite. §16.7's rule earns a corollary — a double that makes a transient fault permanent is not only a coverage gap, it is an amplifier worth keeping, because it is what turned a one-second flap into something anyone could see. And one measurement is recorded rather than fixed: a console rendering a firehose surfaces its drop counter about a minute late, because `tap.data` and `state` handlers share one renderer thread and `appendText` forces a layout per chunk. That is honest behaviour for a control-and-observation tool at serial rates (§5), so the spec that asserts it is tagged slow and runs nightly rather than being tuned until it looks fast.

### 15.39 A session boundary is an edge, and invariant 1 never said otherwise

**Problem.** §6's detach-release frees an on-demand write lock when a pty client leaves, and the reader recognises "a client was here" from evidence the client left *on the master* — a `TIOCPKT_DATA` payload, or the `TIOCPKT_IOCTL` packet a `tcsetattr` provokes (§15.36, invariant 16). That evidence is a **Linux** fact. Darwin's `ptsclose` → `ttyclose` flushes both tty queues at the slave's last close, so a session collapsed inside one poll gap leaves the master byte-identical to no session at all: poll revents, `FIONREAD`, `TIOCOUTQ`, `TIOCGPGRP`, `TIOCMGET`, `TIOCGWINSZ` and the pts inode's timestamps all agree that nothing happened. The consequence is not cosmetic. An `stty`, a health check, any scripted probe that opens the console, reconfigures the line and closes inside 5 ms leaves the write lock held forever, with the endpoint dead to every other writer — measured 20 of 20 against the shipped daemon, `lock.holder` set while `client_present` read `false`, past 30 s, another origin's `send` answering `-32003 … is locked`. It heals only on the next *observed* session or a `lock --steal`. The first diagnosis of this called it unfixable and enumerated the observation vector above as proof; that conclusion followed from the shape of the probe, not from the kernel, and two independent measurements refuted it.

**Decision.** Add `serial_nexus_sys::SessionLatch`: on Darwin a `kqueue` knote registered `EVFILT_READ | EV_CLEAR` on the master, elsewhere inert. `nodes/pty.rs` folds its answer into the existing `saw_session` latch rather than adding a third disjunct — it is the same fact arriving by another road, and one predicate is what keeps the close block reviewable. **Level state cannot carry an edge; that is the whole content of this section.** The enumerated observables above are each a *level*, and a session boundary is a transition, so no amount of looking harder at levels could ever have answered it. What makes this safe rather than a second readiness mechanism is that the latch is polled once per pass, non-blocking, and **never marks the pass productive** — an edge is not data, so `did` stays unset and the idle backoff toward `IDLE_POLL` is untouched. Measured cost: 1.62% → 1.75% of a core idle, against the 74%-of-a-core spin this area's other rules exist to prevent.

**Invariant 1 is not weakened, and the distinction is the reusable part.** That invariant bans `AsyncFd`/epoll as the answer to *"is this fd readable"* on a tty-family fd, because epoll persistently reports a pty master readable while `read` gives `EAGAIN` and starves the single-threaded runtime. Readiness remains `poll(2)` and only `poll(2)`. This asks a different question — *"did a session boundary happen"* — which epoll would have answered no better, and which `poll(2)` cannot answer at all on this kernel. The `meta_gates` grep is for `AsyncFd` and stays exactly as it is; a future reader meeting a `kqueue` in the data plane needs this paragraph, which is why it is a numbered section rather than a comment.

**Two forge sites, both measured, both load-bearing.** The daemon opens the slave itself — §7.2's baseline re-assert, the last-close hostward flush, the reconciliation backstop — and each of those posts an edge the kernel cannot distinguish from a client's. So `watch` swallows the edge its own registration posts (registering on an already-hung-up master posts one immediately, and every pty node starts there because setup primes the slave), and the last-close block discards after running. Neither is defensive habit: removing the first invents a session on the node's first pass, and removing the second makes the handler re-fire on its own footsteps and release a lock no client ever took — which is how the existing suite catches it, in a *different* test than the one this section fixes.

**Implications.** macOS becomes the *stricter* platform for one shape: the bare open→close that Linux deliberately leaves uncovered (nothing readable, nothing to latch on, harmless) does post an edge on Darwin. The asymmetry is recorded rather than levelled — levelling upward means inventing a Linux mechanism for a shape that costs nothing, downward means discarding an edge the kernel is already giving away. `serial-nexus-doctor` grows **P12** beside P7 so the two mechanisms are diffable across kernels and a reader can always tell which one is carrying detach-release in front of them; P12 is gated tightly on macOS, where it is the only mechanism, and presence-only on Linux, where it is inert by design. And the process note is worth as much as the fix: the "unfixable" verdict came from an exhaustive sweep that was exhaustive over the *wrong category*, and what overturned it was two skeptics measuring rather than reasoning — the §15.34 rule (a verifier gets the finding and the tree, never the report) paying for itself again.

## 16. Post-completion review: reliability through simplification

The system is complete, validated on real hardware, and carries the scars of eight adversarial audits. This section reads those scars for structure. The pattern across the serious findings — the exec pump deadlock, the leg stale-status wedge, the waiting-node targetward drain, the phantom lock holder, the stranded waiters — is not carelessness; it is the same three pattern-level rules being re-derived, per node, by hand. The opportunities below make those rules structural. Each carries a disposition; adopted items have executable tasks in the plan's post-1.0 track. As of the review round, items 16.1–16.8 are executed and audited (plan §9), 16.9 remains rejected, and 16.10's deferrals stand. Two later addenda: **16.12** — §15.34's numeric rule generalizes to strings: every identifier that rides the wire or a header carries a stated maximum length, range-checked structurally, because an unbounded name is an allocation and a payload-starver exactly as an unbounded integer is (the `MAX_NAME_LEN` clause is the first instance; any future wire-visible identifier inherits the rule). **16.13** — doctor reports are committed artifacts, not terminal output: a probe run carries its commit, probe-set fingerprint, and date, lands in `docs/doctor/`, and kernel claims in prose must cite a committed report — provenance is recorded, never asserted. A later addendum, 16.11, closes the harness chapter: with the validation suite ported to Rust (§15.31), the three surviving shell scripts (license gate, external-consumer build, and their wait helper) should fold into `serial-nexus-itest` tests that spawn the same tools — retiring bash entirely — while one tempting simplification is recorded as evaluated-and-kept-as-is: the sim doubles stay *subprocesses*, never in-process libraries, because cross-process scheduling is load-bearing realism — it is exactly what exposed §15.19's timer-floor bug, and an in-process double would have hidden it.

**16.1 One boundary-supervisor library (adopt).** Serial, exec, and leg each hand-roll the same lifecycle: spawn, pump two directions as concurrently-polled halves, park a half on producer exhaustion instead of tearing down, pulse a `Notify` on loss, join before transition, back off, retry. Three of the five worst audit findings were instance-level violations of exactly these rules. Extract one supervisor abstraction in `serial-nexus-daemon` that encodes concurrent halves, park-don't-teardown, loss notification, and join-then-transition once — property-tested once — and rebase the three nodes onto it. The invariants stop being conventions the next node type must rediscover.

**16.2 Make the borrow tripwire unrepresentable (adopt).** "A `RefCell` borrow never crosses an `.await`" is upheld today by discipline and audit. Replace raw `RefCell` in the daemon with a closure-only critical-section cell — `with(|state| ...)` where the closure is synchronous by type — and ban `std::cell::RefCell` via clippy's disallowed-types in **every crate that holds daemon state**. The tripwire becomes a compile-shape fact instead of a review item; §15.20's two-lane model loses its only human-enforced clause. *(Amended after review 26.)* The scope clause is not pedantry: this originally said "in `serial-nexus-daemon`", and when the v8 library split (§15.26) moved every line of daemon state into the sibling crate `serial_nexus_daemon`, the ban silently stopped covering the code it was written for — clippy resolves `clippy.toml` from the manifest directory upward through *ancestors*, and a sibling is not one. A lint configuration disarms silently when the code it governs moves, so the durable half of the rule is a test that fails when a crate starts holding daemon state without joining the ban list, not the configuration file itself.

**16.3 One `serial_nexus_sys` crate (adopt).** The unsafe-bearing ioctl and PTY wrappers now exist three times — daemon, doctor, sim — and the macOS port had to gate `TIOCGICOUNT` and `ptsname` per copy; a missed copy is a silent platform break. Collect every raw wrapper into one small internal crate, keep `#![forbid(unsafe_code)]` everywhere else, and the audit surface for unsafe code shrinks to a single file set with the cfg-gating written once. The resolver's promotion from doctor to core (§15.25) is the precedent, applied to the last duplicated layer.

**16.4 The purge invariant, stated once (adopted; done in this revision).** Four scattered purge rules are now one invariant with three instances and one principled exemption (§6). Doc-only, but it is the difference between a future implementer deriving the fourth instance correctly and inventing a fifth rule.

**16.5 Harness and CI hardening (adopt).** Three audits found bugs in the *tests* — a jq precedence tautology that made the soak unfalsifiable, bare sleeps, presence-gated feeds. Adopt: a shared, self-tested assertion helper library (the soak tautology becomes a regression test against the helpers, not a memory); shellcheck plus a jq-lint pass as CI gates; and the full deterministic `--through 8` sweep promoted from local-only to the nightly lane — a validation suite that only runs on the author's machine is a reliability claim on the honor system.

**16.6 State-file durability (adopt, small).** The snapshot is atomic against crashes but not against power loss: fsync the temp file and its directory around the rename. Config mutations are rare, so the cost is unmeasurable; the failure it removes is a truncated state file after an outage.

**16.7 Sim-skip implies hardware coverage (adopt; doctrine).** The project's only genuine real-hardware bug lived on the one path the sim structurally skips (`p5_certify_pair` reports "not a UART" on a pts). Generalize the lesson into the checklist rule: any behavior the sim cannot exercise must either appear on the tiered hardware checklist or be marked *unverified* in the doctor's own report. Untested-because-unsimulatable must be visible, never silent. (Amended by §15.37: browser-reachable behavior left this category — the UI is exercised in real headless Chromium in CI, and the manual checklist retains only rendering fidelity and real-rig interaction.)

**16.8 RPC error-code registry (adopt, small).** Application codes grew ad hoc to five, and the docs audit caught an undocumented one. Define the registry once in `serial_nexus_rpc`, render the docs table from it, and add a test asserting every code the daemon can emit is registered. Drift between behavior and documentation becomes a compile-time or test-time fact.

**16.9 Full readiness unification (evaluated, rejected).** The tempting simplification — move the remaining cold async poll paths onto blocking threads and delete the adaptive backoff — makes the system less reliable, not more. Presence detection cannot use blocking `poll(2)` (level-triggered `POLLHUP` with no client busy-loops), so periodic polling survives regardless; and targetward PTY reads are gated on `may_write`, which lives with the lock on the runtime thread — moving those reads to threads moves the lock consultation across threads, trading a small tuning mechanism for cross-thread arbitration. The hybrid's boundary rule is the simple thing: hot hostward paths on threads, anything lock-gated or inherently periodic on the runtime thread. Recorded so the unification is not re-attempted as a cleanup.

**16.10 Standing deferrals, reaffirmed.** Per-channel wire flow control, the per-open PTY epoch, live-graph surgery verbs, TLS, and the IOKit resolver stay in §14 on their existing rationales; nothing in the completed system raises their urgency. *(Superseded in part by §15.35.)* The edge half of "live-graph surgery" — `connect` and `disconnect` — left §14 when reshaping a graph without a `--replace` outage became the workflow the web editor needed; only `set-attribute` still stands here. The head-of-line property remains bounded to human-scale command traffic in practice, exactly as §9 documented.

## 17. The web console client

`serial-nexus-web` is a separate binary and crate: an RPC client of the daemon on one side, a loopback-only HTTP and WebSocket server on the other. The daemon does not link it, serve it, or know it exists; everything it does rides the §10 surface — `state` and `subscribe` for the console list and lock badges, `tap.open`/`tap.close` for bytes, `send` for input, `info` for provenance — which is §15.16's separation paying out a third time: the web client works unchanged against any embedding daemon (§15.26).

**The interface contract.** A left rail lists every host-facing endpoint as a console — display address, node status, lock holder and waiter count, live via `subscribe`. Selecting a console opens (or foregrounds) its tap on the right: a terminal view rendering the hostward stream, preceded by the replay ring — present by default on every console (§5) — with a visible marker at the splice; the quiet affordance survives only for endpoints an operator has explicitly set to `replay_ring = 0`. The bottom-right single-line input drives the `send` verb; a LOCKED refusal shows the holder by name with an explicit steal affordance — never an automatic steal. The tab's own tap drop counter is shown when nonzero, because §5's honesty applies to browsers too. Two further pages join the console view (§15.35). The *graph page* renders the whole graph — nodes with their types and facing, edges with write modes, every node wearing its `active`/`waiting`/`faulted` status as a live indicator via `subscribe`, lock holders badged on host-facing endpoints. It reads *both* halves of the split rather than one: topology from `dump`, because node kinds and edges are configuration, and status from `state`, because that is what is observed (§15.8). A page that took the whole thing from either would be inventing a third view of the graph that neither verb reports. The *editor page* drives the graph-editing verbs: add and remove nodes from a palette of node types, connect and disconnect edges with the §4 rules enforced by the daemon and surfaced inline, destructive operations behind an explicit confirmation naming what cascades. The layout is the contract; the rendering is presentation and iterates freely under §15.16's rules.

**Implementation stance.** The frontend is static assets embedded in the binary — no Node toolchain, no bundler; console escape sequences are kept legible by the *subset* arm of the choice this section offered (a vendored, permissively licensed terminal renderer, or a minimal ANSI subset), which is the arm "no bundler" makes the affordable one: a dependency-free module rendering SGR reset/bold/dim and the 8/16 colours, honouring `\r`, `\b` and erase-to-end-of-line within the current line, treating the screen-clear sequences as a clear, and **consuming and counting** every other CSI, OSC, DCS and ESC sequence instead of letting it reach the DOM as visible litter — the counter being §5's honesty applied to the one surface where the operator cannot otherwise see what was thrown away. It is a resumable state machine, because at serial rates an escape sequence split across two `tap.data` notifications is the ordinary case rather than an edge case. What it deliberately is not is a terminal emulator: no grid, no cursor addressing, no alternate screen, since a scrollback pane cannot honour state the daemon never sends. It reads decoded text and emits render operations, so the byte log behind the export and the OPFS record stays the raw device stream (§15.32) — the export is a device log, not a transcript. The server side uses permissive HTTP and WebSocket crates under the §13 gate. Taps open lazily per viewed console and are released a grace interval (a minute) after the console stops being watched — watched meaning the console pane showing *and* the tab not hidden, because switching to the graph or editor page hides the console as a unit and leaves a tap streaming with no console on screen at all, which fails even a charitable reading of "on blur" — with the release announced in the terminal so the gap marker that may follow the re-open is attributable, and the re-open running through the same path a fresh selection takes, so §15.38's epoch re-anchor and §15.32's ring-gap marker cover whatever the interval cost. Holding a tap costs a bounded queue and some base64; releasing one costs a re-open that may have to announce a hole, which is why the grace is long rather than tight. The browser link carries base64 chunks relayed from `tap.data` notifications. The UI's behavior is CI-tested in a real headless Chromium driven by a pinned Playwright suite, launched and gated from `serial-nexus-itest` with the standing self-skip discipline (§15.37) — the OPFS splice, the `tap.closed` re-anchor, and the editor flows are asserted in the browser, not assumed from the API.

**Security, stated precisely.** Same posture as the wire (§9), plus one delta the design must not blur: the control socket is mode 0600, but a loopback TCP port is reachable by every local user. The web server therefore requires a per-session bearer token on every request and WebSocket upgrade — generated at startup, printed as a ready-to-open bootstrap URL, then carried as a `SameSite=Strict` session cookie and dropped from the address bar, the cookie named for the listener that set it (`nexus_session_<bound port>`, §15.29) so two consoles keep two sessions instead of evicting one, and *every* value the browser sends under that name checked rather than merely the first, since a sibling-port page can plant a longer-path cookie of the same name and RFC 6265 orders it ahead of the real one — and validates the Host header on every request, loopback included, to shut DNS rebinding; the cookies' SameSite policy doubles as CSRF protection for `send`. The browser's credential is deliberately *split*, because a cookie is never port-scoped and the token is shell-equivalent: the token is offered on the WebSocket upgrade path alone — the one path a browser needs it on, and the path behind which every capability lives — while a second, freshly minted asset credential rides `Path=/`, where a navigation or a `<script src>` can present nothing else. That credential is worth exactly the static assets this project publishes in its own source tree, and is refused on the upgrade; so what a sibling-port service harvests from an ordinary navigation authorizes reading this console's JavaScript rather than commanding its devices (§15.29). The web bridge is a *screening* proxy besides: it parses each frame as exactly one JSON-RPC request — never scans, so a second request smuggled behind a newline is refused, not forwarded — and forwards only verbs on an explicit allowlist (§15.34). With §15.35 the allowlist includes the graph-editing verbs; lifecycle verbs (`shutdown`, `teardown`, `load`) remain outside it. Pre-authentication surfaces are capped and dead-lined (a connection cap taken at the token gate; a **separate, disjoint** pre-auth pool bounded by **evicting its oldest member, never by refusing an accept**; one deadline spanning the TLS handshake and the delivery of a complete request head; a capped head; bounded WS messages), both cookies are `Secure` under TLS — with the residual path scoping narrows but cannot close stated rather than implied: a page *served from* a sibling port is same-*site*, so it can fetch its own `/ws` with credentials and log whatever the browser attaches (§15.29, `docs/security.md`) — and the Origin header is validated against the request's own authority, so a sibling port on the same host is not this origin. *(The pre-auth clause above is amended per review 37, 37-WEBS-6: it previously read "connection cap with a reserve of it held for connections that have not yet presented the token", which was the first WEB-5 shape and is not what shipped. A reserve is enforced by refusal at accept, and the cookie cannot be read until the head is read, so it refuses the operator's own browser exactly as readily as a flood — the audit measured it making the denial four times cheaper rather than closing it. Eviction inverts that: every accepted connection joins the pre-auth pool unconditionally, the oldest is dropped when the cap is exceeded, so a silent peer can no longer deny anyone and can only be the thing evicted, while the operator's browser — always the newest arrival, and out of the pool a round trip later when its cookie is read — is the last candidate rather than the structural victim. The deadline is likewise one instant taken at accept and carried through both phases, not one per phase, so a peer that drips a `ClientHello` and then falls silent cannot hold a slot for twice the stated ceiling (37-WEBS-5). `docs/security.md` carries the measurements.)* The bind policy is three-tiered (§15.29), because the token and the bind restriction solve different layers — the token answers *who may act*, the channel answers *who can read and replay*: (1) the default is loopback plus token, where the kernel is the channel and there is nothing on the wire to sniff; (2) `--tls` (rustls, permissive) plus token is the sanctioned non-loopback mode — the configuration in which "bearer tokens are like API keys" is actually true, since every widely deployed API rides an encrypted channel; and (3) `--insecure-bind` is the leg-precedent named footgun for networks the operator genuinely trusts — the token stays mandatory, and the flag's help text states plainly what is forfeited: every console byte, and the token itself, readable and replayable by anyone on the path. Off loopback, Host validation extends to the configured names and the token moves from the bootstrap URL into a header after first exchange, shrinking the URL-leak vectors (history, referrers, shoulders). The daemon's authorization model is unchanged throughout — the web server is simply a client that holds the socket, and whoever holds the token holds exactly what the web server holds.

**Browser-side history (§15.32).** Scrollback beyond the ring lives where the viewer lives: the web client persists each console's stream in the browser's Origin Private File System — append-only per-console history keyed by the daemon's socket path, the endpoint address and the daemon `instance` nonce, with the endpoint's offset-space `epoch` (§15.38) stored *beside* the bytes rather than folded into the key, spliced exactly using the §10 tap offsets so a reload never duplicates ring bytes into the stored log. The epoch's placement is load-bearing and was chosen against the alternative: keying by it would give every hub rebuild a fresh, empty file and orphan the previous one, so `load --replace` would *destroy* a console's scrollback instead of re-anchoring onto it — which is the failure §15.38 was written to fix, arriving from the other direction. This keeps §15.28's principle intact in its strongest form: the daemon and the graph are untouched, and the party that decided to record is the party whose disk fills — the viewer records for the viewer. Retention is a per-console cap (default 16 MiB, trim-oldest) with export-to-file and clear controls in the UI — `clear` cancels the pending debounced snapshot and detaches the buffer *synchronously* before asking for the delete, and the delete is serialized against writes on the same key, because the confirmation dialog blocks the renderer and a snapshot that came due while it was up otherwise fired at the first `await` and re-created the very record the operator had just confirmed destroying; the client requests `navigator.storage.persist()` and *shows* whether the browser granted it, because origin storage is evictable and honesty about best-effort persistence beats pretending. Two operational consequences are stated plainly: the server binds a stable default port, because the storage origin includes the port and an ephemeral port would orphan history on every restart; and stored console output lives unencrypted in the browser profile — on shared machines, and doubly under the insecure bind tier, clearing site data is part of walking away. Where OPFS is unavailable the client degrades to memory-only history with a visible indicator; there is no second storage backend.

**Posture and non-goals, recorded.** The web client edits the graph (§15.35, superseding the original never-mutates non-goal): a token holder already commands every configured console, and the settled posture is that web access is operator access. The bridge's allowlist scopes that power to the graph-editing and observation verbs — lifecycle verbs stay off the wire from a browser — and the capability statement is made plainly in the security docs: graph editing is daemon-user capability, since a log node writes files and an exec codec runs commands as the daemon's user; whoever holds the token is trusted with exactly that. The web client still does not tail log files: the ring plus browser-side history is the scrollback mechanism, and server-side logs remain an operator recording decision. It is single-daemon per instance in v1 (run two for two daemons). And its authentication story is the token, full stop — no users, no passwords, no sessions to administer; remote access is SSH forwarding or the TLS mode, and the token rides whichever channel is chosen.

### 15.40 One name for the family: the serial-nexus prefix

*(Numbered 15.40, not 15.39. The v14 revision drafted this entry and §15.41 as 15.39 and 15.40, colliding with the already-shipped §15.39 above. The collision was resolved in this direction rather than the other because the committed `docs/doctor/` artifacts cite `§15.39` for the session-boundary edge and §16.13 forbids editing captured output — renumbering that entry would orphan immutable evidence. Citations written against the drafts were converted with it.)*

**Problem.** The binaries and crates carried three naming schemes at once — run-together compounds ending in `d` or `ctl`, bare `nexus-*` crates, and a codec-API crate with no project mark at all. *(The retired spellings are described rather than quoted, because §17.2's gate bans them tree-wide and a document that reproduces the vocabulary is a document that reintroduces it; the gate's own source enumerates them.)* Bare `nexus-*` names collide with an unrelated ecosystem's vocabulary, an installed `doctor` or `sim` says nothing about what it belongs to, and the embedding surface (§15.26) exported crate names an out-of-tree `Cargo.toml` cannot recognize as this project's.
**Decision.** Everything user-visible takes the family name: binaries are `serial-nexus-daemon`, `serial-nexus-ctl`, `serial-nexus-web`, `serial-nexus-doctor`, `serial-nexus-sim`; importable crates are `serial_nexus_daemon`, `serial_nexus_core`, `serial_nexus_rpc`, `serial_nexus_sys`, `serial_nexus_codec_api`; the harness is `serial-nexus-itest`. Directory names stay short — Cargo's `name` field carries the rename, not the tree layout — and `docs/historical/` keeps the old names, guarded by a meta-gate banning them everywhere else. This is a breaking change to the §15.26 extension surface, taken deliberately at 0.x, before external consumers accumulate: the in-tree consumer template converts in the same commit, which is the proof that migration is one `Cargo.toml` edit plus an import rename.
**Implications.** A `ps`, a crash report, or a dependency tree now names the project unprompted; the semver cost is paid at 0.x where it is cheapest; and the grep gate makes the old vocabulary un-reintroducible outside history.

### 15.41 Capabilities, never consumers: business context stays out of the documents

**Problem.** The rename ADR asserted a specific fact about how many parties consume the extension surface and who they are — private business context, promoted to documented fact by inference. *(The offending sentence is paraphrased rather than quoted here, under this entry's own rule: reproducing it would be the same disclosure a second time.)* Review of that sentence surfaced a class: several passages described *who uses* the extension surface rather than *what it supports*.
**Decision.** The documents describe capabilities and never assert the existence, count, or nature of external consumers. Consumer-flavored phrasing is genericized to "out-of-tree"; `closed-source`, `closed repo`, and `known repository` have no legitimate use in this document set and are gate-banned; `downstream` survives only in its data-flow sense (§3's terminology note, the holdover contract) and `proprietary` only where it names a general capability, both under review judgment rather than a gate. One norm is explicitly ranked: this privacy rule outranks the frozen-history rule, so `docs/historical/` gets scrubbed too — leaked context is not decision history.
**Implications.** The extension story reads identically to any external party, which is the point: the documents were always public-shaped; now they are public-safe.

### 15.42 A config verb's reply does not precede the listener it creates

**Problem.** `load` and `add-node` returned the moment every node's `start` had been *called*, and a `role = "listen"` leg's `start` only `spawn_local`s its supervisor — `bind(2)` and `listen(2)` run inside that task, on the same current-thread `LocalSet`, some microseconds later. So the reply announced a graph whose inbound address did not yet exist. A caller that dialled the address it had just configured raced the daemon and lost: `ENOENT` where `bind(2)` had not been reached, `ECONNREFUSED` where it had but `listen(2)` had not. Measured on Linux 7.0.0-29 at a p50 gap of 14 µs, and lost in **40.5% of 1200 trials** under an 8-way load. Nothing else was observable in the meantime: `LegShared::new` initialises status to exactly the `Waiting { reason: "no peer connected yet" }` that a *successful* bind sets, so `state` could not distinguish a listening leg from an unbound one. The reply was a proxy in time for listener readiness (§9), and the only one available.

**Decision.** A config verb holds its reply until every `listen` leg it created has finished its **first bind attempt**. The leg carries a one-shot flag and a `Notify`; the supervisor sets it on the first turn either way; `load`/`add-node` collect the handles *inside* the state critical section and await them *after* the borrow is released, so a `RefCell` borrow structurally cannot cross the `.await` (§16.2, invariant 1). A 5-second bound caps the wait so a node task wedged by a future defect can never make `load` unanswerable — an RPC that never replies is worse than one that replies early, because the early reply at least leaves `state` readable.

**Attempt, not success, and the distinction is load-bearing.** A refused bind resolves the barrier too, having already faulted the node with its reason in `state`. §15.8 puts an environmental failure in the node's status and never in the verb's result; waiting for success would invert that rule, turning a faulted node into a failed `load` and stalling the caller for the whole backoff schedule of an address that may never bind.

**Implications.** The promise the reply always implied is now the promise it keeps, on every platform, without a retry loop in any caller. A harness retry would have made the same symptom go away while leaving every other consumer of the RPC racing — which is why the fix is here and `itest/tests/p6_hostility.rs` is unchanged: those tests become the defect's own regression coverage. The `connect` role gets no barrier: its readiness is the *peer's*, which no reply can promise and no caller should be made to wait for.
