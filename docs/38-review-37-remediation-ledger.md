## The five clusters, and what each fix relocated

The review's thesis — four reviews running now — is that **defects cluster where a rule
lives in prose instead of in a type, a cap, a parser, or a helper.** Each remedy below is
therefore a relocation, and the relocation is the part worth remembering.

**1. Provenance beats timing.** The two worst correctness findings were both a §6 promise
carried by one integration path and absent from another, and both were fixed by *carrying
the fact* rather than re-deriving it later. The leg's receiving-side purge read the
disconnect epoch **after** `rx.recv()` returned, so a peer that sent its commands and closed
in one breath had its whole backlog attributed to the connection that was live when the
channel task next ran — and fired into the device (`37-LEG-1`). The queue now carries
`Inbound { epoch, bytes }`, stamped at enqueue on the pump's read half, which is the only
moment provenance is known. The same shape one level down: `attach_edge` collapsed a *full*
edge inbox and a *closed* one into `is_ok()`, reporting a healthy pump as a dead consumer
and leaving a configured edge hostward-dead for good (`37-DATA-1`). `Full` is now its own
outcome, the attachment does nothing at all, and `connect` refuses it as the transient it is.

**2. A promise implemented for three origins and not the fourth.** §6/§15.23's "a `held`
origin reclaims the moment it frees" was driven from the codec, exec and map targetward
pumps and by nothing at all for a pty — while held-priority in `acquire` denied every *other*
origin on the free lock. Any steal-release, unlock or lease expiry therefore left the
endpoint free-but-untakeable, forever (`37-LOCK-1`). The reclaim now has a non-parking
sibling for boundary origins that own their own lifecycle loop, so the rule is driven from
every place a `held` edge can exist rather than from the three that happened to have a pump.

**3. Terminal events and deadlines must not ride the path they are meant to survive.** A
`tap.closed` was delivered with a discarded `try_send` on the very queue whose fullness is
the reason the client needs the event (`37-CTRL-1`); a parked verb's deadline lived inside a
`select!` arm body that a blocked `write_all` stopped polling, so one non-reading client
stalled every other connection's arbitration on that endpoint (`37-CTRL-2`). Both are now
off the congested path: the terminal event has its own unbounded per-connection lane drained
ahead of the data arm, and the connection's writes no longer block the loop that owns the
deadline.

**4. The one-source rule, one door short.** Review 32 moved `find_usb` and `enumerate_ports`
onto the `class/tty` device listing; bare-serial input still read only the by-id tree, so
`add-node` answered DEVICE_ABSENT for an adapter that was present, in exactly the
no-udev environment §12 grew the rule for (`37-RES-1`). Both directions now read the listing,
the ambiguity guard counts over **devices**, and — the part that is not a copy of `RES-2` —
an ambiguous serial is *refused naming both devices* rather than degraded, because a serial
number pins nothing and there is no single device whose by-path identity would be the right
answer. Four sibling input-arm holes (a by-id link outliving its node, a directory accepted
as a device, `..` escaping `dev_root`, a `:` in a sysfs serial minting an unparseable
identity) went with it, and the form that had **zero** test coverage tree-wide now has it.

**5. Gates that could not fail, and deployments no gate can reach.** Three tree-scanning
meta-gates proved their matchers and never their walkers — so a walker degraded to a
shrunken file set would leave the AsyncFd and RefCell invariants green over nothing
(`37-TEST-1`); the self-exclusion matched a bare file name, exempting any future
`meta_gates.rs` anywhere (`37-TEST-2`); nothing in the suite ever sent the daemon a signal,
so deleting its shutdown arms would pass everything (`37-SEAM-1`). All three now assert
execution. On the deployment side, both packaging majors were semantic mismatches between
the unit's environment and the daemon's assumptions — `DynamicUser` chowning the runtime
directory to a transient group `SupplementaryGroups=` never touches (`37-PKG-2`), and
legacy-state adoption gated off for exactly the deployment that passes `--state-file`
(`37-PKG-1`, fixed in code and guarded in the p13 family).

## Justified rather than closed

Two findings are dispositioned **justify** — the code is right and the record needed
updating. Both were already recorded in `docs/implementation-notes.md` by the review's own
companion commit, and this session made the design annotations that entry called for:

- **`37-CFG-1`** (notes §3.24) — design §11 listed "resolver-input well-formedness" among
  `load`'s structural checks. `Daemon::load` deliberately performs none: `resolve_input`'s
  sole caller in the whole tree is `add-node`, and load-by-identity must never require the
  device or its syntax to be resolvable or cold-start recovery breaks (§3.20(a)). The
  design sentence was the stale side and is now qualified.
- **`37-TOOL-3`** (notes §3.23) — design §15.21 promises the P5 rig certificate performs
  "deliberate baud *and parity* mismatches … break reception". The shipped probe does a baud
  mismatch and a local break-ioctl acceptance; the missing pieces ride the Tier-3 checklist
  suite. `probes.rs` is unchanged and §15.21 is annotated to the shipped scope.

## Two process notes

**1. Fail-first proof was obtained, not argued, for every behavioural guard.** AGENTS.md §9
requires it for `37-LEG-1`, `37-LOCK-1` and `37-CTRL-2`; it was taken for those and for
essentially every other new guard, by reverting the specific fix **in place** and rebuilding
— never `git stash`. The observed failure text is in each row's *Guard / proof* column
below, verbatim. Two of them are worth reading before touching the code they pin:
`37-LEG-1`'s pre-fix run delivered a dead peer's entire 256-byte backlog into the graph with
`purged_on_reconnect: 0`, and `37-DATA-1`'s reachability was re-derived empirically with a
throwaway pipelined-RPC probe (reply id 108 came back `consumer_live:false` deterministically)
before any test was written.

**2. A shared build directory silently invalidates a fail-first proof.**
`cargo test -p serial-nexus-itest --test <name>` does **not** rebuild the daemon binary the
harness spawns; it runs whatever is in `target/debug/`. Every in-place revert in this session
had to be followed by `cargo build -p serial-nexus-daemon-bin` before the itest meant
anything. This is the same class as review 32's "a guard that drives the fix cannot fail
against the code that lacked it", one layer down in the toolchain.
