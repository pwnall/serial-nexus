# AGENTS.md — operating manual for serial_nexus implementation sessions

## §1 What this repository is
A Rust workspace implementing the serial_nexus design: `serial-nexus-daemon` (lib `serial_nexus_daemon`), `serial-nexus-ctl`, `serial-nexus-web`, `serial-nexus-doctor`, `serial-nexus-sim`, the `serial-nexus-itest` harness, and the libraries `serial_nexus_core`, `serial_nexus_rpc`, `serial_nexus_sys`, `serial_nexus_codec_api`. Directory names stay short; Cargo `name` fields carry the family prefix (design §15.40). The normative documents are the current design/plan pair named in §2; §ref numbers always point at the current design. Older doc versions, frozen reviews, and remediation ledgers live in `docs/historical/` and are records, not law.

On macOS `SNX_CROSSOVER` additionally *enables* the `cu.usbserial` scan, which no longer fires unasked — plan §18 item 5) (`--no-fail-fast` per §6 — this is platform validation), preceded once by `scripts/bless` (build + install + one `setcap`; `--all` for both profiles). CI enumerates loops from tools (`cargo fuzz list`), never hand-kept lists; meta-gates assert *execution*, not file existence, and a scanning gate proves its **matcher** as well as its walker — plant the violation in every spelling it claims to cover.

## §4 Invariants with tripwire status (violations die in review)
- A `RefCell` borrow never crosses an `.await`; `std::cell::RefCell` is clippy-banned in the daemon — use the critical-section cell (§16.2).
- `AsyncFd` is banned workspace-wide for pty masters (§15.18; read the P8 annotation before re-litigating).
- `unsafe` lives only in `serial_nexus_sys` (§16.3); everything else is `#![forbid(unsafe_code)]`.
- Every targetward framer fragments oversize chunks via the one shared helper; never skip-on-encode-error (§5, §15.27).
- Purge is one invariant, three instances (§6); the tap/ring mirror never affects `discarded_unattached` (§15.32).
- Every numeric attribute and every wire-riding identifier carries a stated, structurally checked maximum (§15.34, §16.12).
- The web bridge parses exactly one request per frame and forwards only the allowlist; lifecycle verbs stay off it (§15.34, §15.35).
- Sim doubles are subprocesses, HUP-tolerant, never busy-waiting, idle-CPU asserted (§15.31, §15.36).
- The privileged helper is narrow by construction (§15.45): one capability, argv-only, no environment read, no `exec` while blessed, and its device argument is a kernel-verified sysfs USB **port name**, never a path. Giving it a verb that accepts a filesystem path dissolves every one of those bounds at once and is a design amendment, not a patch.

## §5 Documents: amend-first, and the ledgers
When implementation and design disagree, amend the design first (a new §15 entry; annotate superseded entries, never rewrite them), then implement. Deviations land in `docs/implementation-notes.md` §3 as numbered entries. Review findings get a remediation ledger mapping every id to a disposition — including deliberate declines; silently re-fixing a declined item is a defect. Consult the prior reviews' cleared-candidate tables before filing anything.

## §6 Harness doctrine (plan §3)
Fill-then-commit protocol clients (deadline expiry never consumes); completeness asserted only where the design promises it, with `hostward_buffer` provisioned and cited where a test needs it; the loss fingerprint is `received + dropped_slow_consumer == sent`; the sim marks `timed_out` so a deadline is never read as a drop; run quiet and under parallelism; never filter suite output before the failing test's name is captured. When you are validating a **platform** rather than a change, pass `--no-fail-fast`: `cargo test --workspace` stops at the first failing test *binary*, which makes "one known failure" and "four unknown ones" look identical (this cost six consecutive red macOS pushes — `docs/macos.md`, 2026-07-28). **A byte counter is read while the client that fed it is still open** — asserting it after the client's close asserts that the kernel retained the bytes, which Linux does and Darwin does not — measured, not assumed: doctor P13 reads `retains` on Linux 7.0.0-29 (close in tens of µs — 20/10/13 across three captures — 64/64 recovered in all three shapes, `docs/doctor/linux-7.0-2026-08-05-tier3.json`) and `waits-then-discards` on Darwin 24.6.0 (600104 µs, 0 of 64 with no reader; 23 µs, 64 of 64 when the master drains first; 29 µs, 0 of 64 for an `O_NONBLOCK` slave — `docs/doctor/macos-24.6.0-2026-08-05-tier3.json`). So on Darwin such a guard is **not a coin flip but a deadline**: against a blocking slave it has ~600 ms of slack over the daemon's 200 µs–5 ms reader cadence and only reddens on a genuine reader stall, while an `O_NONBLOCK` slave loses the bytes unconditionally in 29 µs — which is why the rule stays absolute rather than becoming "safe on Darwin" (notes §3.29 carries the fix, the rule, and the seven latent siblings; `docs/macos.md`, 2026-08-04).

## §7 Kernel evidence
No one-way decision on single-kernel evidence. When two credible sources disagree about kernel behavior, prefer the kernel-independent design and add a doctor probe (P6–P11 pattern) that measures instead of assumes. A kernel that differs is `degraded` with the observation named, never `unsupported`. Kernel claims in prose cite a committed `docs/doctor/` report (its commit, fingerprint, and date — §16.13), never a terminal scrollback.

## §8 The box, and the tree
Measure the machine before attributing anything to code: load average, competing builds, core count. Flake reproduction rates are meaningless under uncontrolled load. Do not trust `git stash` to bisect a large uncommitted change set — reproduce defects by *reverting the specific fix* in place. Capture failing-test names verbatim before any rerun. A run that died mid-replug leaves a USB adapter deauthorized — it comes back with `./.snx-bin/debug/serial-nexus-replug authorize --port <p>`, or with a physical unplug/replug, and `serial-nexus-replug status --port <p>` says which state it is in.

## §9 Verification protocol
A regression guard is valid only with fail-first proof against the unfixed tree. Root-cause claims for flaky or security-relevant findings get an independent adversarial verifier that has **not** read the diagnosis — only the finding and the tree — and the tree must not move while verification runs (the v12 audit returned 35/43 wrong verdicts because it moved). Record refuted diagnoses; they are as load-bearing as confirmed ones. A guard must assert the property the product **promises**, never a proxy for it — in space (a Linux-only observable standing in for a portable one) or in time (a file's existence standing in for a listener's readiness). A proxy is what makes a guard pass on the box it was written on and fail, or worse pass vacuously, everywhere else; the tell that you found the real property is that the portable form comes out *stricter* on the platform of record, not weaker.

## §10 Context hygiene (design §15.41)
Documents, notes, ledgers, reviews, and comments describe *capabilities*, never consumers: no assertions about the existence, count, or nature of external users or any business context. Say "out-of-tree", never `closed-source`, `closed repo`, or `known repository` (gate-banned tree-wide, including `docs/historical/` — the privacy rule outranks the frozen-history rule). `downstream` is allowed only in its data-flow sense; `proprietary` only as a general capability. When quoting older material that violates this, paraphrase.

## §11 Naming
Binaries `serial-nexus-*`; importable crates `serial_nexus_*`; directories short and carrying no family prefix at all — `core/`, `rpc/`, `sys/`, `daemon/` (the library), `daemon-bin/` (the thin binary), `ctl/`, `web/`, `sim/`, `replug/`, `doctor/`, `itest/`, `codec-api/`, `codecs/reference/`. A gate that scans the filesystem therefore spells the *directory*, never the crate. Old names only in `docs/historical/`, the frozen reviews, and the captured `docs/doctor/` artifacts, enforced by the meta-gate. The extension surface is exactly `serial_nexus_codec_api` plus the `serial_nexus_daemon` entry API, semver'd, proven by the external-consumer template built from the consumer's position on every push.
