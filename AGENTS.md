# AGENTS.md — operating manual for serial_nexus implementation sessions

## §1 What this repository is
A Rust workspace implementing the serial_nexus design: `serial-nexus-daemon` (lib `serial_nexus_daemon`), `serial-nexus-ctl`, `serial-nexus-web`, `serial-nexus-doctor`, `serial-nexus-sim`, the `serial-nexus-itest` harness, and the libraries `serial_nexus_core`, `serial_nexus_rpc`, `serial_nexus_sys`, `serial_nexus_codec_api`. Directory names stay short; Cargo `name` fields carry the family prefix (design §15.40). The normative documents are the current design/plan pair named in §2; §ref numbers always point at the current design. Older doc versions, frozen reviews, and remediation ledgers live in `docs/historical/` and are records, not law.

The **rig lane** is by hand on the crossover box and is not part of the default gate set (CI has no adapters and the tests correctly self-skip): `SNX_CROSSOVER=required SNX_REPLUG=required SNX_TLS=required SNX_RIG_FLOW=required SNX_WEB_UI=required SNX_CROSSOVER_A=… SNX_CROSSOVER_B=… SNX_REPLUG_DEV=/dev/serial/by-id/… SNX_REPLUG_DEV_B=/dev/serial/by-id/… cargo test --workspace --no-fail-fast` (`SNX_WEB_UI=required` joined the documented lane spelling at the v16 landing — notes §3.68's session gated the browser lane under it (the 835 once attributed to that session is unreconciled with its verbatim record — plan Status row), and this line had omitted it; `SNX_REPLUG_DEV_B` joined it 2026-08-12 — notes §3.75 — because without it `identity_survives_a_replug_that_renumbers_the_tty` self-skips and `SNX_REPLUG=required` turns that skip into a hard failure, so the documented lane could not go green on the rig it describes) (`SNX_TLS=required` is the third instance of the one `required` mechanism, covering `web_tls_round_trip`'s two silent skips — no `curl`, and a sandbox that cannot bind `0.0.0.0:0` with `--tls`; plan §3 rule 11, notes §3.57. `SNX_RIG_FLOW=required` is the fourth, and the first whose precondition is *measured* rather than declared: it covers the two `rts-cts` end-to-end tests, which skip on a **3-wire** bench — §5's own stated design assumption, so a rig that answers no is legitimate and `SNX_CROSSOVER=required` deliberately does not redden it (design §15.52, notes §3.63). On macOS `SNX_CROSSOVER` additionally *enables* the `cu.usbserial` scan, which no longer fires unasked — plan §18 item 5) (`--no-fail-fast` per §6 — this is platform validation; **drop `SNX_RIG_FLOW=required` on a bench P5 measures as 3-wire *or* as `UNREADABLE`, and `SNX_WEB_UI=required` without `node`** — all are legitimate answers and forcing them fails the lane for the operator's cabling, transport or toolchain, notes §3.80 and §3.102. **A CDC-ACM bench's handshake reading is never a cabling statement, and the *word* it prints depends on the stack** (§15.62, **corrected 2026-08-21 by §15.68**): the CTS bit is manufactured rather than read, so *no instrument in this tree can tell what the cable is* — but **which** constant is manufactured is stack-dependent, and only one of them is legible as an instrument failure. Linux `cdc_acm` synthesises **high**, which reads `UNREADABLE handshake … this is not a 3-wire answer`; Apple's CDC-ACM driver leaves it **low**, which is bit-identical to a bare conductor and prints **`3-wire: no handshake lines carried`** — a cabling sentence, on the same two adapters and the same cable (plan §18 item 92). **This line said `UNREADABLE` was "the CDC-ACM answer" until a Mac falsified it**, which is the stale-claim defect §2 names. **Do not re-crimp a CDC-ACM bench on either reading**, and do not read `3-wire` from one as a cable fact), preceded once by `scripts/bless` (build + install + one `setcap`; `--all` for both profiles). CI enumerates loops from tools (`cargo fuzz list`), never hand-kept lists; meta-gates assert *execution*, not file existence, and a scanning gate proves its **matcher** as well as its walker — plant the violation in every spelling it claims to cover. **The tell for a gate that asserts nothing: its passing output is identical to its not-running output.** Three instances are recorded — `jq` without `-e`, a gate whose step never ran because the step ahead of it was red (notes §3.77), and a SKIP-line grep whose subject `cargo test` captures before it can be grepped (notes §3.78). **Two further registers of the same tell, both found 2026-08-14** (notes §3.101): a gate that asserts the **previous** answer — a guard pinning a *decision* rather than a *mechanism*, which a decision change silently converts into the thing holding the defect in place; and a gate whose assertion is strictly **weaker than the comment above it claims** — e.g. `a.contains(X) && a.contains(Y)` where `X` is a substring of `Y`, so the conjunction collapses and a second, unrelated arm satisfies it. The second is the hardest to see, because the comment is what a reviewer reads. **Two more of the weaker-than-its-comment register landed 2026-08-16** (notes §3.112), and both were found by hardware rather than by reading: `p8_packaging.rs`'s "the table's own vocabulary is closed: three class words and no others", enforced as *each of three words appears at least once*, so a fourth class passes and `measured (partially)` always did (plan §18 item 84, filed not fixed); and `P14_BUDGET`'s "a hard wall-clock stop on the whole search", checked only *between* rungs while a rung is uninterruptible — one search ran **2089 s** against a 180 s budget (item 83). The lesson both carry: a constant's comment is a claim about *placement*, and placement is exactly what a reviewer's eye slides over. **A sixth register landed 2026-08-17** (§15.65): a gate whose **stimulus is gentler than the product's**. `web/ui-tests/fixture.mjs` selects a console with Playwright's `.click()`, which presses and releases in one tick *and* auto-retries on a detached element — forgiving in exactly the two ways a mouse is not — so no number of specs could have caught a rail that was rebuilt under the press. Measured: 0/20 clicks lost at 0 ms of dwell against 16/20 at 150 ms, on the same unfixed tree. Drive the property the way the product is actually driven. One remedy covers all: **plant the defect the guard names and watch it redden** — fail-first proof applied to the guard's *stated* property, not merely to its code.

## §4 Invariants with tripwire status (violations die in review)
- A `RefCell` borrow never crosses an `.await`; `std::cell::RefCell` is clippy-banned in the daemon — use the critical-section cell (§16.2).
- `AsyncFd` is banned workspace-wide for pty masters (§15.18; read the P8 annotation before re-litigating).
- `unsafe` lives only in `serial_nexus_sys` (§16.3); everything else is `#![forbid(unsafe_code)]`.
- Every targetward framer fragments oversize chunks via the one shared helper; never skip-on-encode-error (§5, §15.27).
- Purge is one invariant, three instances (§6); the tap/ring mirror never affects `discarded_unattached` (§15.32) — and neither does an armed `tap.wait`, which is the same mirror with a matcher on it.
- The pattern wait's matcher is fed from the hub with **no queue between hub and matcher** (§10), is linear-time and bounded at compile (a backtracking engine on the runtime thread is an operator-reachable DoS, §15.56), resets its lookback window on a feed gap so a match never spans unobserved bytes, and counts toward mirror activity exactly as an open tap does. Expiry is a typed *result*; teardown is a typed *error* (`-32008`). Do not collapse those two.
- Every numeric attribute and every wire-riding identifier carries a stated, structurally checked maximum (§15.34, §16.12).
- The web bridge parses exactly one request per frame and forwards only the allowlist; lifecycle verbs stay off it (§15.34, §15.35).
- Sim doubles are subprocesses, HUP-tolerant, never busy-waiting, idle-CPU asserted (§15.31, §15.36).
- The privileged helper is narrow by construction (§15.45, amended by §15.55): **two** capabilities — `cap_dac_override` for the sysfs write, `cap_fowner` for the ACL grant — argv-only, no environment read, no `exec` while blessed, and its device argument is a kernel-verified sysfs USB **port name**, never a path. Giving it a verb that accepts a filesystem path dissolves every one of those bounds at once and is a design amendment, not a patch. The `grant` verb (§15.55) is that amendment executed the other way: it takes a port name, derives the device nodes itself, grants to `getuid()` and never to an argv uid, and never opens the node. Adding a capability is likewise an amendment — `REQUIRED_CAPS` in `devprep/src/linux/install.rs` is the one place the set is written.

## §5 Documents: amend-first, and the ledgers
When implementation and design disagree, amend the design first (a new §15 entry; annotate superseded entries, never rewrite them), then implement. Deviations land in `docs/implementation-notes.md` §3 as numbered entries. Review findings get a remediation ledger mapping every id to a disposition — including deliberate declines; silently re-fixing a declined item is a defect. Consult the prior reviews' cleared-candidate tables before filing anything.

## §6 Harness doctrine (plan §3)
Fill-then-commit protocol clients (deadline expiry never consumes); completeness asserted only where the design promises it, with `hostward_buffer` provisioned and cited where a test needs it; the loss fingerprint is `received + dropped_slow_consumer == sent`; the sim marks `timed_out` so a deadline is never read as a drop; run quiet and under parallelism; never filter suite output before the failing test's name is captured. When you are validating a **platform** rather than a change, pass `--no-fail-fast`: `cargo test --workspace` stops at the first failing test *binary*, which makes "one known failure" and "four unknown ones" look identical (this cost six consecutive red macOS pushes — `docs/macos.md`, 2026-07-28). **A byte counter is read while the client that fed it is still open** — asserting it after the client's close asserts that the kernel retained the bytes, which Linux does and Darwin does not — measured, not assumed: doctor P13 reads `retains` on Linux 7.0.0-29 (close in tens of µs — 20/10/13 across three captures — 64/64 recovered in all three shapes, `docs/doctor/linux-7.0-2026-08-05-tier3.json`) and `waits-then-discards` on Darwin 24.6.0 (600104 µs, 0 of 64 with no reader; 23 µs, 64 of 64 when the master drains first; 29 µs, 0 of 64 for an `O_NONBLOCK` slave — `docs/doctor/macos-24.6.0-2026-08-05-tier3.json`). So on Darwin such a guard is **not a coin flip but a deadline**: against a blocking slave it has ~600 ms of slack over the daemon's 200 µs–5 ms reader cadence and only reddens on a genuine reader stall, while an `O_NONBLOCK` slave loses the bytes unconditionally in 29 µs — which is why the rule stays absolute rather than becoming "safe on Darwin" (notes §3.29 carries the fix, the rule, and the seven latent siblings; `docs/macos.md`, 2026-08-04).

## §7 Kernel evidence
No one-way decision on single-kernel evidence. When two credible sources disagree about kernel behavior, prefer the kernel-independent design and add a doctor probe (P6–P11 pattern) that measures instead of assumes. A kernel that differs is `degraded` with the observation named, never `unsupported`. Kernel claims in prose cite a committed `docs/doctor/` report (its commit, fingerprint, and date — §16.13), never a terminal scrollback.

## §8 The box, and the tree
Measure the machine before attributing anything to code: load average, competing builds, core count. Flake reproduction rates are meaningless under uncontrolled load. Do not trust `git stash` to bisect a large uncommitted change set — reproduce defects by *reverting the specific fix* in place. Capture failing-test names verbatim before any rerun. A run that died mid-replug leaves a USB adapter deauthorized — it comes back with `./.snx-bin/debug/serial-nexus-devprep authorize --port <p>`, or with a physical unplug/replug, and `serial-nexus-devprep status --port <p>` says which state it is in.

## §9 Verification protocol
A regression guard is valid only with fail-first proof against the unfixed tree. Root-cause claims for flaky or security-relevant findings get an independent adversarial verifier that has **not** read the diagnosis — only the finding and the tree — and the tree must not move while verification runs (the v12 audit returned 35/43 wrong verdicts because it moved). Record refuted diagnoses; they are as load-bearing as confirmed ones. A guard must assert the property the product **promises**, never a proxy for it — in space (a Linux-only observable standing in for a portable one) or in time (a file's existence standing in for a listener's readiness). A proxy is what makes a guard pass on the box it was written on and fail, or worse pass vacuously, everywhere else; the tell that you found the real property is that the portable form comes out *stricter* on the platform of record, not weaker.

## §10 Context hygiene (design §15.41)
Documents, notes, ledgers, reviews, and comments describe *capabilities*, never consumers: no assertions about the existence, count, or nature of external users or any business context. Say "out-of-tree", never `closed-source`, `closed repo`, or `known repository` (gate-banned tree-wide, including `docs/historical/` — the privacy rule outranks the frozen-history rule). `downstream` is allowed only in its data-flow sense; `proprietary` only as a general capability. When quoting older material that violates this, paraphrase.

## §11 Naming
Binaries `serial-nexus-*`; importable crates `serial_nexus_*`; directories short and carrying no family prefix at all — `core/`, `rpc/`, `sys/`, `daemon/` (the library), `daemon-bin/` (the thin binary), `ctl/`, `web/`, `sim/`, `devprep/`, `doctor/`, `itest/`, `codec-api/`, `codecs/reference/`. A gate that scans the filesystem therefore spells the *directory*, never the crate. Old names only in `docs/historical/`, the frozen reviews, and the captured `docs/doctor/` artifacts, enforced by the meta-gate. The extension surface is exactly `serial_nexus_codec_api` plus the `serial_nexus_daemon` entry API, semver'd, proven by the external-consumer template built from the consumer's position on every push.
